# 性能与界面维护

本文记录现行性能边界与可复现验收方法。模块细节见 [渲染层](modules/renderer.md)、[API Server](modules/server.md)；命令以 `package.json` 为准。速度、内存和安装包大小必须区分实测值与代码层面的改进，不能用依赖数量或单测时长代替用户体验。

## 启动与资源

页面由 `AppShell` 按访问加载。不要在一个空闲回调里导入全部页面：动态导入仍会解析和执行模块，集中预热会重新引入启动负担。首次进入页面沿用转场内部的 Suspense。

3D 歌词的 Canvas、效果和舞台位于独立 `LyricsScene` 模块；关闭、纯歌词或禁用 3D 时不加载。流体背景加载期间使用静态霞光；进入 3D 歌词或详情封面时卸载流体。最小化和迷你状态卸载主窗口可视层，但音频引擎、歌词与悬浮窗同步继续运行。

2.3.1 增加游戏模式：播放栏的手柄按钮、设置中的「游戏模式」和托盘菜单均可进入。主窗口退居托盘，临时收起迷你条与壁纸，暂停封面取色、Apple 可视化捕获及账户界面轮询；音频、队列、媒体键与已启用的全局快捷键继续运行，不更改音质。模式只在本次运行中生效。

游戏模式沿用原有播放、全局快捷键及桌面歌词开关，不增加模式专属选项。未开启桌面歌词时不请求歌词或运行歌词时钟；开启时自动使用单行、暗色底框，暂停逐字高亮、发光与自动宽度，MusicKit 行时钟降为 250ms。退出游戏模式恢复原迷你条、壁纸和歌词外观；选择「显示主窗口」则返回完整播放器。macOS 单击托盘打开菜单，双击返回；Windows 单击返回、右键打开菜单。托盘支持播放/暂停、切歌、静音和音量调整，曲目与播放状态变化时才刷新菜单。

未使用的 `@react-three/drei`、`@react-three/postprocessing` 已移除，锁文件减少 49 个包条目，其余版本保持不变。这减少后续安装和打包所携带的依赖；当前已有 `node_modules` 不自动清理，安装包实际节省量须由相同平台的打包结果验证。

## 渲染与主线程

| 路径 | 现行边界 | 回归重点 |
|---|---|---|
| 我的库曲目 | 本地、离线、最近播放使用固定行高虚拟列表，曲目行 56px、步长 58px | 大库只挂载可视行；筛选排序后的点击索引与完整队列一致 |
| 播放栏 | 进度和音量由独立子组件订阅 | 进度更新不重渲染整条播放栏；拖动仍触发 seek |
| 播放队列 | 弹层仅淡入和平移，避免缩放干扰虚拟列表坐标 | 当前歌曲位于大队列后部时，打开与重开都能直接居中显示 |
| 歌词 | 已排序时间轴使用二分查找，同时间取最后一行；索引和进度合并通知 | 前后 seek、正负偏移、空歌词、逐字进度边界 |
| Apple 歌词时钟 | 仅 MusicKit 播放时运行 50ms 定时器 | 暂停、切传输或卸载停止；暂停调整偏移立即更新 |
| 封面取色 | 普通切页不重复采样，切歌与退出刷歌时更新 | 过期图片结果和旧补间不能覆盖新封面 |
| 主题同步 | 仅相关主题、字体和透明度设置变化写根样式 | 调整无关音质、歌词布局不会重复写全局样式 |
| 播放持久化 | 只保留当前队列及顺序的序列化缓存，进度写入复用 | 替换队列详情后失效；剥离 URL、随机顺序和旧 schema 恢复 |

队列及曲目详情沿用不可变更新，不能原地修改后期待序列化缓存失效。持久化仍会同步写入完整 localStorage 数据，缓存优化减少重复遍历和序列化，不能描述成消除了写盘开销。

## API 与磁盘

本地库按目录维护最多 4 个快照，合并并发读盘；封面、歌词与音频按 ID 查 Map，每次仍异步 stat 以检测外部替换或删除。扫描与移除按目录串行，临时文件原子替换后失效快照。只读结果复制，避免返回引用被修改后污染缓存。

更新包以流读取并增量计算所需摘要，单遍同时校验 SHA256/SHA512；保留长度和摘要的失败规则。并发启动复用同一任务，不能为了提速跳过摘要、安全来源或损坏缓存处理。

## 视觉约束

延续黑白双主题、封面取色和圆角控件。导航使用轻量表面，避免常驻模糊叠加；歌单标题预留两行，对齐网格底边；播放栏根据窗口宽度分配空间。键盘焦点必须可见，歌曲行内的红心与保存操作在聚焦时显示。滑轨视觉保持细线，点击区域为 20px。

设置导航宽屏占据真实列宽，1280px 及以下使用横向导航，不能通过展开浮层盖住表单。遵循系统减少动态效果设置；不新增字体下载，不改变用户自定义字体。

## 验收

逻辑与依赖调整运行：

```bash
npm run typecheck
npm test
```

只在检查代码分割、依赖清理或准备交付产物时补跑 `npm run build`。检查 `out/renderer/assets/` 中独立的 `LyricsScene-*`、`LiquidEther-*`、`three.module-*`，并核对入口的静态 import 链，不能仅凭文件存在断言首屏不加载。

界面和资源生命周期使用 `npm run dev` 实测：

1. 在 960px、1280px 和宽屏检查导航、搜索、播放栏与设置；深浅主题均测试选中项 hover 和 Tab 焦点。
2. 用至少 5,000 首测试数据滚动本地/离线库，核对 DOM 行数有界、末尾可达、筛选排序归顶、点击实际队列和移除后的列表。
   播放队列另测顺序和随机模式：当前歌曲位于第 597 / 4,001 个显示位置时打开、关闭再打开；不滚动就应看见居中的当前歌曲。入场缩放会使 `getBoundingClientRect()` 与 `scrollTop` 的单位不一致，且动画结束不触发列表重算，曾导致打开队列空白。
3. 打开普通歌词再切 3D，返回详情和主界面；核对单窗口仅一个可见 WebGL 场景。最小化、恢复和迷你切换保持播放与进度同步。
4. Apple Music 播放/暂停/seek/调整偏移，并检查后台授权与播放会话没有受到影响。
   游戏模式另测原桌面歌词开关、托盘与全局快捷键切歌、退出恢复；对比同曲目进入前后的任务管理器数据，不能用逻辑测试替代 CPU/GPU 实测。
5. 用同一曲库和同一动效预设录制 Performance/Memory，比较启动与切页的长任务、滚动帧率及多次切歌后的资源；跨机器数字不能直接比较。

本轮已通过类型检查、143 个测试文件 / 1,117 项测试、构建及独立复审。隔离浏览器在 1100 × 600 视口使用各 5,000 首本地与离线测试曲目，首屏各挂载 18 行，滚至末尾仍少于 40 行；末尾点击保留完整队列和索引 4,999，筛选、倒序、离线专辑搜索、播放全部与最近播放索引均正确。行高实测 56px、步长 58px，无重叠与页面错误；这些数字反映 DOM 数量边界，不代表帧率或速度提升比例。

Electron 主窗口已检查深浅主题、探索、曲库、设置、播放栏以及普通歌词与 3D 场景切换，并恢复原深色与普通歌词偏好。构建入口静态 import 链不包含 Three.js、LyricsScene 或 LiquidEther；启用流体背景时仍会按功能需要加载 Three.js。自动化测试不能代替完整播放、DRM、GPU 与跨平台实测；Windows、登录中的 Apple 会话和发布安装包仍需对应环境验收。

## 后续测量优先级

- 离线状态批量查询目前仍可能遍历全部缓存及逐文件 stat；先测大缓存请求耗时，再决定构建按来源索引或缩小校验范围，保留缺失文件清理语义。
- 音频代理等待上游响应头期间的取消与超时仍可进一步完善；已有流式传输断开与背压回归测试，不能以性能改动削弱 Origin、token、上游 URL 边界。
- Apple 账户状态轮询与本地存储同步写入的耗时，需在真实登录、断点恢复和主窗口隐藏场景下测量后调整。

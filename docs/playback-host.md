# 独立播放宿主与游戏模式

2.4.0 开发分支使用独立隐藏 Chromium 音频窗口承载正式运行时。游戏模式在宿主就绪后销毁主界面窗口及其渲染进程，保留播放、队列、刷歌、睡眠、历史、下载、账号和桌面控制。宿主不装配 React 页面或 Three.js 场景，仍复用现有 `AudioEngine`；这是独立音频渲染进程，尚非原生音频后端。

## 生命周期与状态

- `electron/modules/playback-host.ts` 创建隐藏沙盒窗口，使用独立持久分区 `persist:simplemusic-playback-v1`。音频宿主和壁纸按需禁用后台节流，主 UI 接受后台节流。
- `playback-host.html` → `src/playback-host.ts` 在迁移确认后动态装配运行时。原 UI 分区保留完整旧存档作为备份，目标只记录来源，避免双份队列挤占配额；逐项读回确认后才标记迁移完成。失败不启动核心、不删除原数据。冷启恢复暂停，下载恢复后等待手动继续。
- `playback-shared-stores.ts` 列出状态与动作白名单。UI store 是后台投影，动作经主进程转发；引擎入口只返回只读时钟，频谱读取缓存。需要结果的操作等待真实回执。
- UI 先订阅再连接，完整快照和增量共用 session/revision；旧版本丢弃，缺口重连。队列、歌词等仅变化时发送，没有可见 UI 时停止传输；恢复不重新加载歌曲、恢复旧存档或重建随机顺序。
- 命令顺序受理并立即调用，异步完成独立回执；慢解析不阻塞暂停和新切歌。下载控制器留在宿主，等待取消使用请求 ID；UI 失联不取消已经入队的下载。
- 登录 Cookie 交换、退出和失效统一由宿主处理。账号 epoch 先于 Provider 通知投影，旧会话失效消息不能污染新账号。
- 托盘、迷你条、全局快捷键和 Media Session 由宿主执行。UI 输入与模态阻挡态同步后台，销毁/重载/崩溃清除录入锁；设置菜单先恢复 UI 再发送命令。刷歌随活导航恢复，窗口释放不触发离开。

IPC 分别验证固定 UI/宿主窗口、主 frame 和精确入口。单次 UI 命令限制 8 MiB、等待请求最多 128 个，连接 30 秒、业务动作 120 秒超时；合法宿主快照不套用输入长度限制，避免大队列造成静默丢状态。频谱限制 4096 项，按可见 UI 的短租约采集，隐藏后停止 Apple 捕获与频谱循环。后台不预热封面图片；游戏模式暂停取色、壁纸与纯播放歌词工作，保留的桌面歌词沿用降耗规则。

正常退出先保存断点并补报收听，再释放运行时、销毁后台和关闭 API，保留 1.8 秒补报及整体 8 秒兜底。`BrowserWindow.destroy()` 不触发 unload，不能依赖它保存状态。宿主崩溃时停止旧音频并关闭独立 Apple 会话，关闭全部悬浮窗并清除游戏模式的窗口恢复快照，保留用户开关偏好且不抢回主界面；显式开启与迟到更新都不能重新创建失效悬浮窗。迷你条开启失败也不会退出游戏模式。显示中文故障提示，不自动另启播放；需重启应用。回退代码时原 UI 备份仍在，后台迁移后的新存档不自动覆盖旧分区。

- 开发应用实测 UI 与宿主 PID 不同；销毁 UI 后两首静音 WAV 自然结束并推进，原 UI PID 消失。托盘暂停、暂停定位、无 UI 睡眠停止、Dock 重建通过，重建不重载音频。
- 重启保留暂停断点，旧 UI 空队列没有覆盖后台。刷歌用本地音频 feed 夹具，真实进入会话后销毁 UI 仍自动切卡，返回保持当前卡，主动离开恢复原暂停队列和断点；未据此认定真实在线推荐已验收。
- 生产构建 `file://` 入口续播、UI 进程释放、恢复不重载、无 UI 睡眠停止通过。最终构建真实终止宿主进程后没有第二路音频，现存界面及重载失败页显示中文错误。

同一 120 秒本地静音 WAV，生产构建、未生成安装包，保持 CDP 连接，未开启无障碍强制渲染。每阶段按 1 秒采样 14 次，丢弃前 4 次，取应用所有进程汇总中位数：

| 指标 | 界面可见 | 游戏模式 |
|---|---:|---:|
| 工作集汇总 | 729.9 MiB | 578.3 MiB |
| Electron CPU 指标汇总 | 1.338% | 0.196% |

工作集汇总可能重复计算共享页，不能视为独占内存；样例只说明本机释放 UI 的效果，不代表游戏帧时间或跨机器预算。[汇总样本与检查项](reviews/2.4.0-playback-host-verification.json)、[恢复后的正式界面](reviews/assets/2.4.0-independent-playback-restored.png)。

## 后台任务与异常悬浮窗收尾

后续收尾通过类型检查、253 个文件 / 2218 项 Vitest 及独立复核，另用开发应用和隔离用户目录实测：

- 两项真实 HTTP 缓存导出仍在途时进入游戏模式，主 UI 销毁后宿主继续完成。正常退出保存另四项任务；同配置冷启保持 queued + paused，没有自动导出，界面点击“继续队列”后完成。六份 WAV 的 SHA256 与缓存原件一致，完成后恢复存档清空。这是本地缓存夹具，不能据此认定真实平台鉴权下载或字节续传通过。
- 迷你条控制独立宿主暂停并返回主界面成功。正常模式和游戏模式分别强制崩溃真实宿主进程，歌词、壁纸与迷你条全部关闭，不重建音频、不抢回主界面；Dock 恢复显示停止提示，旧窗口恢复快照与迟到更新均不能重开悬浮窗。

## 系统媒体时钟收尾

暂停后连续定位和暂停时修改倍速现在立即更新系统 positionState，普通播放进度仍按每秒同步。类型检查、253 个文件 / 2220 项测试及独立复核通过。macOS 隔离配置、真实独立宿主和本地 WAV 实测中，销毁 UI 后调用已注册媒体回调，暂停、连续定位、播放、上下首和媒体键开关均生效；恢复 UI 接回暂停/倍速/队列且不重载音频。原生 MediaSession 方法实际执行，但没有操作实体媒体键或系统控制中心，也不替代设备切换验收。[验证记录](reviews/2.4.0-media-controls-verification.json)。

## 正式宿主音频与冷启动验收

在 `56a3352` 的正式开发入口、macOS 隔离用户目录下，销毁主 UI 后，MP3、FLAC、M4A、AAC、OGG、Opus 六种自生成短音频连续自然结束并推进。WMA WMAv2 明确报 `MEDIA_ERR_4` 并停留本曲，可手动切到 WAV 继续播放；这验证错误处理，不代表 WMA 解码通过。

三次连续合成 `devicechange` 事件只触发一次实际 `AudioEngine.load`，保留当前断点、1.5 倍速和队列；恢复等待中暂停不会迟到起播，已暂停时设备事件不重载。事件到恢复的链路通过，未切换真实硬件。恢复界面的 IPC 可读取当前后台状态且不重载音频；它单独不证明客户端展示正确。

另行正常退出并冷启，真实 UI 镜像与 DOM 显示当前 WAV、42 秒暂停断点及八曲队列；倍速按既有规则回到 1。观察到引擎无源且暂停、没有音频请求记录；手动播放从断点继续，客户端进度和状态同步。格式/恢复运行只监控了宿主的 Runtime 异常，未据此宣称全部窗口无异常。静音样本不代替音质、保音高听感或所有编码变体验收。[完整证据及范围](reviews/2.4.0-formal-audio-verification.json)。

# 2.2.0 问题记录

> 本文记录 `dev/2.2.0` 开发期间确认的问题及其处理状态。

## P1：关闭迷你播放器后主窗口无法恢复（功能已修复，性能待采样）

记录日期：2026-09-15

修复日期：2026-09-15

### 修复结果

- 关闭按钮与封面入口统一调用“退出迷你模式”流程：销毁迷你窗口、同步关闭设置并显示聚焦主窗口。
- 关闭按钮文案由“收起到托盘”改为“退出迷你模式”。
- 明确启用迷你窗口后台节流；隐藏歌词时不再随歌词换行重复唤醒和发送空数据。
- 增加 IPC 关闭行为、按钮语义和后台节流回归测试。

### 修复前表现

进入迷你播放器后，主窗口会隐藏。点击迷你播放器的关闭按钮时，迷你窗口被收进托盘，但主窗口没有重新显示；macOS Dock 中也无法找到可恢复的普通窗口，用户容易误以为应用已经退出或卡死。

代码线索：`overlay:miniplayer-close` 修复前调用 `hideMiniPlayerToTray()`，与“关闭迷你模式并返回普通窗口”的交互预期不一致；`docs/modules/overlays.md` 中原有说明也与实际行为存在漂移。

### 预期行为

- 迷你播放器的关闭按钮表示“退出迷你模式”，应关闭迷你窗口，并显示、聚焦正常主窗口。
- 同步关闭 `miniPlayerEnabled`，避免重启应用后再次自动进入无法恢复的迷你状态。
- “仅隐藏到托盘”应保留为明确的托盘操作或主窗口关闭策略，不与迷你播放器的关闭按钮混用。
- 即使主窗口或迷你窗口发生异常关闭，托盘、Dock 或再次启动应用仍应能恢复主窗口。

### 性能要求

- 迷你播放器保持独立轻量渲染入口，不加载 3D、WebGL、探索页、完整播放器页面或平台数据模块。
- 暂停或静止时不运行持续动画帧循环；进度同步维持当前最高 1 Hz，其他更新由状态变化事件驱动。
- 保持 Electron 默认后台节流；关闭迷你模式后销毁其 `BrowserWindow`，释放事件监听、定时器和渲染进程资源。
- 真机分别在播放和暂停状态观察 5 分钟，记录迷你模式相对正常主窗口的 CPU 与内存增量；出现持续 CPU 活跃或内存持续增长即不通过。

### 验收状态

- [x] 从正常窗口进入迷你模式，点击关闭按钮后普通窗口立即出现并获得焦点。
- [x] 主窗口重新出现在 macOS 应用窗口中，可再次进入迷你模式。
- [x] `sync-off` 会把 `miniPlayerEnabled` 持久化设置落回关闭。
- [x] IPC 与窗口生命周期回归测试覆盖关闭、状态回落和重复启停。
- [ ] 补充托盘恢复与应用二次启动的自动化覆盖。
- [ ] 完成播放/暂停两种状态各 5 分钟的 CPU、内存真机采样，并确认无持续增长或不必要的高频任务。

### 当前性能基线

- 生产构建中的迷你播放器入口脚本约 16.8 KiB，未引入主应用页面或 WebGL 资源。
- 2026-09-15 暂停态单次快照中，迷你模式相关进程 CPU 均为 0.0%；新增迷你渲染进程 RSS 约 129 MiB。RSS 包含 Chromium 共享映射，仅作为后续对比基线，不能替代 5 分钟增量采样。

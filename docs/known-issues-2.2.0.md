# 2.2.0 问题记录

> 本文记录 `dev/2.2.0` 开发期间确认的问题及其处理状态。

## P1：关闭迷你播放器后主窗口无法恢复（功能与同步降耗已修复，整机长时性能待验收）

记录日期：2026-09-15

修复日期：2026-09-15

### 修复结果

- 关闭按钮与封面入口统一调用“退出迷你模式”流程：销毁迷你窗口、同步关闭设置并显示聚焦主窗口。
- 关闭按钮文案由“收起到托盘”改为“退出迷你模式”。
- 明确启用迷你窗口后台节流；隐藏歌词时不再随歌词换行重复唤醒和发送空数据。
- 增加 IPC 关闭行为、按钮语义和后台节流回归测试。
- 迷你状态改为首次完整快照、后续变化字段增量，忽略重复值；preload 提前接收并重放首屏状态，避免订阅就绪竞态。
- 紧凑宽度不再同步隐藏歌词，关闭进度展示时停止周期推送；移除进度条每秒 250ms 补间，保留 1Hz 进度与透明外观。

### 修复前表现

进入迷你播放器后，主窗口会隐藏。点击迷你播放器的关闭按钮时，迷你窗口被收进托盘，但主窗口没有重新显示；macOS Dock 中也无法找到可恢复的普通窗口，用户容易误以为应用已经退出或卡死。

代码线索：`overlay:miniplayer-close` 修复前调用 `hideMiniPlayerToTray()`，与“关闭迷你模式并返回普通窗口”的交互预期不一致；`docs/modules/overlays.md` 中原有说明也与实际行为存在漂移。

### 预期行为

- 迷你播放器的关闭按钮表示“退出迷你模式”，应关闭迷你窗口，并显示、聚焦正常主窗口。
- 同步关闭 `miniPlayerEnabled`，避免重启应用后再次自动进入无法恢复的迷你状态。
- “仅隐藏到托盘”应保留为明确的托盘操作或主窗口关闭策略，不与迷你播放器的关闭按钮混用。
- 即使主窗口或迷你窗口发生异常关闭，托盘、Dock 或再次启动应用仍应能恢复主窗口。

### 性能要求

- 迷你播放器保持独立轻量渲染入口，不加载 3D、WebGL、探索页、完整播放器页面或平台数据模块。
- 暂停或静止时不运行持续动画帧循环；进度同步维持当前最高 1 Hz，其他更新由状态变化事件驱动。
- 保持 Electron 默认后台节流；关闭迷你模式后销毁其 `BrowserWindow`，释放事件监听、定时器和渲染进程资源。
- 真机分别在播放和暂停状态观察 5 分钟，记录迷你模式相对正常主窗口的 CPU 与内存增量；出现持续 CPU 活跃或内存持续增长即不通过。

### 验收状态

- [x] 从正常窗口进入迷你模式，点击关闭按钮后普通窗口立即出现并获得焦点。
- [x] 主窗口重新出现在 macOS 应用窗口中，可再次进入迷你模式。
- [x] `sync-off` 会把 `miniPlayerEnabled` 持久化设置落回关闭。
- [x] IPC 与窗口生命周期回归测试覆盖关闭、状态回落和重复启停。
- [x] 补充托盘恢复与应用二次启动的自动化覆盖（托盘单击、双击、菜单恢复与已有主窗口下的二次启动）。
- [x] 去除重复全量同步、隐藏歌词与隐藏进度的更新，以及进度补间产生的额外合成帧；独立复审与真实桥接冒烟通过。
- [ ] 确认整机真实播放无持续增长（开发版播放/暂停各 5 分钟已采样；生产版隔离界面采样不替代音频、图片加载与主窗口共同运行时的长时验收）。

### 当前性能基线

- 最新生产构建中的迷你播放器入口脚本约 17.5 kB（不含共享 React chunk），未引入主应用页面或 WebGL 资源。
- 2026-09-15 暂停态单次快照中，迷你模式相关进程 CPU 均为 0.0%；新增迷你渲染进程 RSS 约 129 MiB。RSS 包含 Chromium 共享映射，仅作为后续对比基线，不能替代 5 分钟增量采样。
- 2026-09-15 macOS 开发版暂停态 5 分钟采样（20:04:49–20:09:51，每 10 秒一次，共 31 次）：全部播放器进程 CPU 均为 0.0%；迷你渲染进程 RSS 从 128640 KiB 到 128720 KiB，增量约 80 KiB，未见持续增长。其余进程整体 RSS 下降。
- 同日开发版播放态采样（20:11:09–20:16:10，同样 31 次，含自然切歌）：迷你渲染进程 CPU 采样峰值 4.9%，RSS 从 137088 KiB 到 170464 KiB，净增约 32.6 MiB；期间有回落，但末段仍上升，不能据此确认长期稳定，也不能仅凭 RSS 认定泄漏。
- 普通窗口播放态单次对照中，主渲染/GPU 进程 CPU 分别为 23.1%/30.9%；迷你模式对应采样峰值为 12.1%/21.8%。这是开发版不同时间点的粗对照，不是严格的同曲生产版性能基准。普通窗口相关进程 RSS 合计约 751.5 MiB，迷你模式首尾约 878.3/915.1 MiB；总 RSS 含共享映射，不等于独占物理内存。
- 验收后已恢复普通窗口与原曲暂停态；后续检测到用户操作而停止自动化，未继续覆盖断点或取消测试曲的固定状态。

### 同步与合成降耗验证（2026-09-15）

- 原因边界：迷你条新增独立 Chromium 渲染进程，主窗口只是隐藏，仍承担音频播放。RSS 求和包含共享映射，不能解释为实际新增的独占物理内存；macOS 同时观察 `process.getProcessMemoryInfo().private` 与 JS/Blink 堆。
- 同配置 360×80 透明生产版界面、无封面、人工 1Hz 状态的 90 秒隔离对照：原补间进度的样式重算净增 656 次；仅移除补间后净增 90 次。稳态渲染/GPU CPU 约从 0.14%/0.67–0.70% 降至 0.018–0.025%/0.044–0.055%，这是隔离界面开销，不是整个播放器的节省比例。
- 原补间组私有内存约 23.3–26.5 MiB，末次主动回收后约 22.9 MiB；无补间组约 22.9–25.1 MiB，回收后约 22.5 MiB。两组节点数 56、JS 监听器数 140 不变；未复现此前开发版 RSS 净增约 33 MiB，不能据此认定那次采样是泄漏或已经完全解决。
- 修复后的生产版隔离界面连续 300 秒接收 1Hz 增量及 3 次模拟切歌：私有内存 24161→24801 KiB（净增 0.625 MiB），采样范围约 22.9–25.5 MiB，期间多次回落；末次主动回收后 23169 KiB（约 22.6 MiB），Blink allocated 527→493 KiB，JS used heap 1714→2095 KiB。节点 56、监听器 140 全程不变，未见持续对象累积。末段样式计数停止增加，未记录遮挡状态，不把该轮所有时段当作持续可见渲染的严格 CPU 基准；CPU 对照采用上面的 90 秒两组。
- 去掉模糊后的 CPU/内存没有显著进一步收益，因此保留原透明模糊外观。不通过强制定期 GC 掩盖内存问题；主动回收仅用于测试比较。
- 真实生产版 preload 冒烟通过：完整快照早于 React 订阅、增量保留元数据、切歌、宽度展开歌词、进度关闭/恢复、播放/上一首/下一首/seek/退出/返回主窗口的控制事件。主窗口恢复行为由既有窗口生命周期测试覆盖。
- 补充独立 Electron 下真实 React effect 重渲染检查（使用隔离测试 store，不读用户数据）：进度关闭/恢复、暂停/播放、紧凑/展开歌词、迷你关闭/重开和卸载均通过；定时器最多一个，暂停、隐藏进度、关闭或卸载后归零。该临时冒烟 harness 不计入 Vitest 测试数量。
- 类型检查、88 个测试文件共 632 项测试、生产构建、差异格式检查与独立复审通过。未提交、推送或升级版本。

## 离线能力收尾（2026-09-15）

已修复并加入回归检查：

- 主动下载失败后继续尝试后续候选，试听候选不落盘。
- 取消解析或下载立即释放前端任务，旧会话迟到结果不再写回。
- 离线命中先于平台参与判断；跨源离线保留原内容曲目并记录真实音频身份，离线切歌不补报听歌打卡。
- 缓存转固定能够持久化；坏文件在线回退绕过缓存，不删除固定文件。
- 状态查询去重、分批与失效保护；共享删除确认计入其他固定别名。
- 目录维护期间拒绝新增固定承诺；损坏索引的路径、哈希和别名校验失败后走备份或保守隔离。
- 保存接口覆盖完整下载、Range 读取、别名隔离、试听/不安全 URL/错误 key 拒绝、上游失败、长度不符和取消清理。

验证：类型检查、85 个测试文件共 619 项测试与生产构建通过；macOS 开发版实测完整缓存转为“已保存”、“本地离线”播放、迷你窗口开启和退出恢复主窗口。

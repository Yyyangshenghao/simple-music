# 伴奏生成架构与内存验收

本轮保留按需启动、任务结束即退出的隔离分离实例，优先使用原生 ONNX WebGPU，替换生成期间浏览器 WASM 运行库的开销。原生引擎只在分离实例中按需加载，播放器主实例不加载它。模型、精度、队列、用户保存目录和“我的伴奏”的行为保持现有约定。

本记录保留引擎切换时的历史对照，尚未包含后续的块间让步调度。真实页面滚动暴露的卡顿及当前生成耗时取舍见[卡顿修复验收](2026-10-27-karaoke-responsiveness.md)。

## 最终实现

- `electron/main.ts` 同步设置启动开关，再按角色加载入口；普通实例动态加载 `application.ts`，分离实例不初始化播放器、平台接口和内嵌服务依赖。主进程构建 chunk 保持与入口同目录，避免破坏 preload、图标和页面的相对路径。
- 分离 Worker 继续负责 FFT、分块、逆变换及 OPFS WAV 写入；原生引擎读取已安装的模型，只通过私有 preload IPC 接收单块频谱。HQ3 每块 12 MiB、KARA2 每块 8 MiB，同时最多一次推理，不传整首 PCM。
- 私有 IPC 校验窗口、主 frame、模型和输入尺寸；Worker 用任务 ID 与块序号匹配回复，丢弃迟到响应。输出视图如带额外底层内存则裁剪后返回，各块输入和输出张量在 `finally` 中释放。
- 原生初始化不可用时沿用浏览器 WebGPU；不静默改用高内存 CPU 推理。旧会话释放失败则结束任务，不启动第二套引擎。完成、失败、取消或内存保护触发后，沿用原有完整进程退出及等待退出机制。
- 原生成功时不向页面下载模型二进制和 WASM。保留上一轮的立体声缓冲直接转移、分块写盘与文件上传，详见[上一轮验收](2026-10-27-karaoke-memory.md)。开发态预先优化浏览器回退依赖，防止首次点击生成触发 Vite 重新优化并重载页面。

## 整应用对照

环境为 Apple M5、32 GiB、macOS arm64、castLabs Electron 42.11.0+wvcus，Web 与原生 ONNX Runtime 均为 1.30.0。输入为固定主歌、高潮和尾奏片段重复拼接的 180 秒、44.1 kHz 双声道 PCM16 WAV，共 32 块。每轮使用新资料目录，预装同一模型，通过实际播放宿主队列生成，主窗口保持可见并播放本地音频。

RSS 每 100 ms 按进程父子关系汇总整个测试 Electron 及全部子进程，包含主界面、播放宿主、分离实例和瞬时测量子进程，不包含 Vite。多进程 RSS 会重复计入部分共享页，不能直接解释为释放了同等物理内存，也不是内存硬上限。本轮口径与上一轮仅统计分离实例工作集的口径不同，不叠加计算降幅。

| 同入口受控对照 | 浏览器 WebGPU 峰值 | 原生 WebGPU 峰值 | 降幅 | 总耗时：浏览器 → 原生 |
| --- | --- | --- | --- | --- |
| HQ3 半精度，三轮平均 | 2140.6 MiB | 1786.8 MiB | 16.5% | 17.89 s → 17.22 s |
| HQ3 标准，带 GPU 计数的一轮 | 2236.0 MiB | 1803.0 MiB | 19.4% | 22.45 s → 21.75 s |

半精度三轮浏览器峰值为 2116.1 / 2148.6 / 2157.3 MiB，原生为 1782.0 / 1788.8 / 1789.5 MiB。标准模型另一次原生结果为 1801.0 MiB、21.98 s。浏览器对照仅由临时测试入口让原生初始化返回不可用，产品没有新增引擎开关。

带 GPU 计数的半精度对照为 2157.3 → 1789.5 MiB，下降 17.0%。相应系统级 IOAccelerator 峰值为 1189.2 → 1187.9 MiB，基线为 375.5 → 395.3 MiB；标准模型峰值为 1910.1 → 1854.5 MiB，基线为 373.5 → 381.3 MiB。GPU 计数每 250 ms 采样，包含其他应用和驱动波动，不与 RSS 相加，也不据此宣称降低了 GPU 内存峰值。

主界面用实际窗口中的小画布持续绘制 64 个矩形，采集动画帧间隔。半精度三轮超过 50 ms 的帧数为浏览器 7 / 5 / 11，原生 1 / 3 / 3，P95 为 7.0 → 6.7–6.8 ms。标准模型为 11 → 6 帧。播放状态及播放进度保持前进；该检查不等于音频无断续的听测或系统级音频延迟检测。

## 输出与生命周期

同一实际应用解码、前后处理及 WAV 写入路径下，两种模型的浏览器与原生输出均逐字节一致，文件均为 31,752,044 字节：

- HQ3 标准：`4995f9745243d0e4ac3b7de1913770587d8e66dcda8aa173ab7f5e2144241066`
- HQ3 半精度：`d75fb21a684704bc0f7cf53d6fc15d9c3c0d0a3ee24bd569a614a93e9f9f5456`

真实 Electron 流程完成 HQ3 标准、半精度和 KARA2 生成；验证切歌后原任务继续、推理中取消不发布成品、取消后立即重试、单声道生成、迷你条 preload 和桌面歌词开关。单元用例额外覆盖等待原生回复时取消、迟到回复、错误张量格式、并发拦截、初始化回退及会话释放失败。

## 试验后未采用

| 方案 | 测量结果及决定 |
| --- | --- |
| 同一 Electron 内隐藏分离窗口 | 半精度峰值可降至约 1812–1880 MiB，但超过 50 ms 的界面帧增至 41–64 帧，部分配置 P95 达 47.1 ms；继续保留隔离。 |
| 隐藏窗口停止绘制 | 半精度 1820.0 MiB，但总耗时 37.30 s，长帧 63；未采用。 |
| `--in-process-gpu` | 半精度约 2159.7 MiB，对原隔离入口的 2184.5 MiB 收益小且可能受波动影响；未引入该开关。 |
| 仅缩小分离启动入口 | 半精度约 2144.0 MiB，单独收益有限；保留轻量入口，并配合原生 GPU。 |
| 原生 CPU 推理 | 12 秒独立单进程探针：双线程峰值 2683.1 MiB / 5.45 s，单线程禁用 memory pattern 为 1702.2 MiB / 7.27 s；同长度原生 WebGPU 探针为 312.7 MiB / 1.98 s。该探针不含播放器界面且不含 GPU 驱动全部内存，不与整应用表格混比。未作为默认或自动回退。 |

## 打包、验证与限制

新增运行库固定为 `onnxruntime-node@1.30.0`。打包只保留目标平台与架构的二进制，并把绑定及相邻动态库一起解包到 ASAR 外；macOS 两个内容相同的 dylib 只保留绑定实际链接的 `libonnxruntime.1.dylib`，避免重复约 43 MiB。当前 arm64 原生绑定及核心库合计 44,856,768 字节（约 42.8 MiB），这是安装体积的新增成本，不是常驻空闲内存。`.npmrc` 阻止安装时下载未使用的 CUDA/TensorRT，已验证 npm 配置传递及模拟 Linux x64 安装分支。

- 类型检查通过；全量 Vitest 为 370 个文件、3458 项测试通过；独立只读复核通过。
- `npm run build` 通过；实际开发态验证了主窗口、播放宿主、分离及两个悬浮窗流程，主进程资源路径未因动态入口改变。
- 按实际 electron-builder FileMatcher 筛选的运行库装入 ASAR，并在 Electron 中从 ASAR 加载原生 WebGPU 模型完成推理；输出 12 MiB，字节偏移为 0，底层缓冲区等长，重复 dylib 已排除。
- 本轮没有制作安装包或执行签名。Windows 实机、Intel Mac、其他显卡及最终安装包仍需平台验收。当前 npm 包没有 macOS x64 原生绑定，Intel Mac 初始化不可用时走已有浏览器 WebGPU 回退；该回退有单元及本机强制回退流程验证，不等于 Intel 实机验证。
- 输入仍整首解码，模型的 GPU 张量仍有明显开销。保留原有准入预算和运行时内存保护，没有降低保护门槛。单机固定片段的结果不能保证每首歌、每种硬件都有相同降幅。

采样、逐轮汇总、输出摘要、ASAR 探针与检查结果见 [measurements.json](assets/2026-10-27-karaoke-architecture/measurements.json)。

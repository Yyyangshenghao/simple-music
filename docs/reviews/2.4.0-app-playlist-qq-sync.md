# 2.4.0 应用歌单手动同步 QQ 音乐

目标 `dev/2.4.0`，功能分支 `feature/qq-app-playlist-sync`。用户要求为 QQ 加入此前网易云的应用歌单同步能力。本阶段不升级版本、不推送或发布。

## 行为与边界

- 全 QQ 歌曲且登录、启用平台时，在应用歌单详情提供同步。混合来源不筛掉其他平台后同步；QQ 名称最多 20 个字符。
- 首次新建私密歌单，之后手动更新同一目标名称和歌曲集合。按平台、账号分别持久保存关联，不保存 Cookie 或会话凭证；失败保留检查点供重试，清除旧成功标记。
- QQ 没有找到可证实的歌曲排序写接口；页面注明顺序以 QQ 端为准，本地排序不会误报成可同步的云端变更。不会清空重塞来模拟排序。
- 先补歌并读回确认，再删除差集；完整分页核验歌曲身份。旧档类型缺失时先查询确认，不猜 0。每次要求本人私密普通歌单，公开或特殊目录不写入。
- 改名保留最新简介、封面、标签和可见性。删除本地歌单保留云端；已关联空歌单可明确点击清空云端歌曲。
- 上游各层码与最终读回均通过才报告成功；80105 展示拒绝原因，既不假成功，也不自动注销账号。

## 验证

已通过类型检查及全量 Vitest（265 文件、2334 项）。路由覆盖首次私密创建、名称和差集、顺序边界、870 首分页/分批、80105 各层错误、静默漏歌、元数据保护、账号切换、创建检查点、写锁、空歌单、未知类型解析、公开目标和 MID 冲突。

独立复核发现并修正旧能力断言、未知类型默认 0、私密检查依赖内存及删除前身份分支问题；复跑 82 项通过，无新增代码阻塞。

真实 macOS Electron 开发窗口使用隔离 userData 与模拟平台响应，验证首次入口、失败重试同目标、重命名、顺序提示、刷新持久化不含凭证、换号独立关联、空目标更新、退出禁用、混合来源、名称上限、浅色最小视口及网易云回归。机器记录见 [交互验收](2.4.0-app-playlist-qq-sync-verification.json)。

本机 QQ 登录态只读 `GetPlaylistByUin` 成功。专用私密测试歌单的创建、加歌、改名、删歌、幂等及清理脚本已准备，**尚待用户授权，未执行真实账号写入**。历史普通 Web 写入曾返回 80105，不能由源码、匿名读取或模拟响应推断已可写。当前官网签名通道与现有 musicu 通道不同，本阶段不绕过账号验证。未在 Windows/Linux 实机检查。

创建检查点最多 64 条且只在当前服务进程内保留；正常回复后客户端保存目标。创建已被上游接受但响应完全丢失/服务退出时，不能保证重试绝不重复新建。已关联目标被云端删除或不可读时，停止并报错，不把网络错误误判为删除后另建。

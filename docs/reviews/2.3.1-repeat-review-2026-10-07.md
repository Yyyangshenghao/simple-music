## Findings

### P2：每日推荐整列表追加和下载使用合成歌单 ID

位置：[PlaylistDetailView.tsx:220](../../src/components/Playlist/PlaylistDetailView.tsx#L220)。

触发：从探索打开网易每日推荐，选择标题旁更多菜单中的添加到播放队列或全部下载。

`ProviderRecommendationSection` 通过 `playlistFromTracks` 创建 ID 为 `netease:daily-songs` 的合成歌单，同时将完整歌曲传入详情的 `initialTracks`。标题菜单始终传 `tracks=[]` 和 `collections=[displayPlaylist]`；`resolveBatchTracks` 因而调用 `getPlaylistSkeleton('netease:daily-songs')`，将合成 ID 作为网易歌单 ID 发到 `/api/playlist/tracks`，导致整个操作失败。逐曲或多选路径不走这个错误 ID。

建议：有完整 `initialTracks` 的合成列表使用现有曲目做整列表操作；真实平台歌单继续使用集合展开。补充每日推荐整列表追加和下载回归用例。

### P3：带搜索条件返回歌手页过早完成滚动恢复

位置：[ArtistPage.tsx:94](../../src/pages/ArtistPage.tsx#L94)。

触发：在歌手热门单曲中搜索并滚动，进入其他详情后返回；原歌手资料及热门歌曲仍在缓存内。

缓存使 `artistLoaded` 和 `songsLoaded` 首帧为 true，但 `useArtistSearch` 初始为 `songs=[]`、`loading=false`，到被动 effect 才开始搜索。滚动恢复的 layout effect 在空搜索列表上设置 `scrollTop`，位置被页面高度截断后仍置 `scrollRestored=true`；搜索结果返回后不再恢复原位置。

建议：搜索模式等待本次搜索初始化及完成，再恢复滚动；补充缓存命中、搜索条件及非零滚动位置同时存在的返回用例。

### P3：清空队列后系统媒体状态和进度仍残留

位置：[player.ts:483](../../src/stores/player.ts#L483)，相关同步：[media-session.ts:25](../../src/lib/media-session.ts#L25)。

触发：播放中的歌曲已同步系统媒体进度，再清空队列。

`stop()` 将当前曲目清空、状态设为 idle、时长设为 0。媒体订阅清除 metadata 后调用 `syncPositionState`，该函数因时长为 0 提前返回，留下旧的 `playbackState='playing'` 及 positionState。独立复审执行真实同步模块复现了 playing/180 秒/30 秒状态在清空后残留。

建议：无当前曲时同步 `playbackState='none'` 并调用无参数 `setPositionState()` 清空进度；状态同步不受有效时长判断阻断。补充播放后清空队列的系统媒体状态回归。

# 2.4.0 歌单双向同步验收

目标 `dev/2.4.0`，工作分支 `feature/playlist-sync-workflow`。本阶段只本地集成开发代码，不升级、推送或发布。范围约定见 [需求与合并规则](../specs/2026-10-16-playlist-sync-workflow.md)。

## 行为

应用歌单详情按「检查变更 → 拉取并合并 → 推送应用更改」手动执行。首次创建私密歌单，按平台和账号保存关联、共同基准与最近结果，不保存 Cookie 或会话凭据。旧关联缺基准时，用户明确选择保留应用内容准备推送，或采用云端内容；不猜历史覆盖内容。

双方独立新增、删除和改名可合并；不同改名、删除与另一端移动同一歌曲、不同重排等冲突须逐项选择。拉取仅更新应用歌单；仍有本地修改时继续提示推送。明确推送以应用为准，移除云端额外歌曲；已关联空歌单可清空歌曲并保留目标。检查后云端再变则拒绝旧推送，拉取期间本地/账号/基准变化也会丢弃旧结果。

普通加歌批次失败不撤销已完成的删歌、改名或排序，报告实际已加入、已移除与未完成项。可确认的实际云端内容成为下一次基准，本地期望不变；重试先重新检查，只补差异。最终无法读回时数量为未知，不能显示零或整体成功。完整初始列表、身份、会话、本人普通歌单及 QQ 私密保护仍保留，无法确认时不安全删除。

网易云推送名称、歌曲及实际可用歌曲的相对顺序。QQ 推送名称与歌曲集合，不能推送顺序；拉取可采用云端顺序，本地重排不产生推送任务。创建检查点在服务进程内保留最多 64 项，成功回执丢失后的重试复用目标；应用与云端目标分别加锁，在途最多 32。

## 验证

2026-10-17 最终 `npm run typecheck` 与全量 Vitest 通过：271 文件、2614 用例。独立复核覆盖完整基准/三方合并/推送链路，并独立复跑增量 QQ 72 项与 UI 26 项；无未修复阻断问题，差异检查通过。复核发现的 QQ 成功回执丢失后重复创建、删除冲突缺少曲名均已修复并回归。界面机械检测一次通过（`[]`）。

实际 macOS Electron 开发窗口使用独立 userData、独立端口；未读取真实账号凭据，未操作原有云端歌单。网易云端到端验收经过当前源码的真实本地 HTTP 路由，上游函数全部替换为内存合成账号与歌单；QQ 页面使用合成快照/报告，写入路由由独立回归用例覆盖。验收包含：

- 首次创建与基准落盘、双方独立新增和云端改名的合并及推送。
- 名称、删除与移动、顺序三类冲突，未选全禁提交，Escape 关闭、重新打开清选择。
- 加歌批次失败但删除和改名生效，刷新后保留部分报告，重试仅补缺歌且不重复建歌单或删除。
- 检查后云端变化，零写入拒绝旧推送，重查拉取保留新云端歌曲。
- 改名已执行但最终回读失败，数量显示待确认，恢复读取后可以重新对齐。
- QQ 拉回云端更新、推送本地名称/集合并保留顺序边界，旧关联明确对齐。
- 已从应用删除但云端仍在的冲突歌曲补全曲名，按平台过滤并丢弃快照/换号/卸载后的迟到信息，读取失败明确显示歌曲 ID。
- 深浅主题、1536×864 和 960×540 内容视口、无横向溢出、小窗口弹窗内部滚动及键盘焦点、存档无会话凭据、无页面异常。

上述实际界面 12 组检查全部通过，无页面异常。机器记录见 [交互验收结果](assets/playlist-sync-workflow/results.json)。

## 真实验证缺口

本轮没有使用真实网易云或 QQ 账号执行双向同步写入，也未在 Windows/Linux 实机验收。已有 QQ 上游真实写通道验证不等同于本轮双向流程已真实联网验收。平台限流、网络和内容可用性仍可能产生部分结果，用户可检查后补齐。

这不是完整 Git 历史：没有提交记录、回滚或后台自动同步。版本检查只保证写入前与已检查快照一致，平台不提供原子条件写入，不能保证写入过程中另一客户端同时修改时完全无竞争。

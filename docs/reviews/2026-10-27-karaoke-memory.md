# 伴奏生成内存优化验收

本轮沿用单任务队列、所选模型和原有内存保护，调整音频数据的生命周期：立体声解码结果直接转移给 Worker；WAV 逐块写入私有临时文件，上一块写完后才继续推理，生成后以磁盘 File 上传。正常完成、上传失败及取消均清理临时文件，异常退出残留在下次任务开始前清理。

## 性能对照

环境为 macOS arm64、Apple M5、32 GiB 内存、castLabs Electron 42.11.0+wvcus、onnxruntime-web 1.30.0。测试输入为固定主歌、高潮和尾奏片段重复拼接的 180 秒、44.1 kHz 双声道 PCM16 音频，不代表对不同完整歌曲的质量评测。每组使用全新进程，处理 32 个推理块，优化前后各两轮。

进程组峰值按 `app.getAppMetrics()` 的 `workingSetSize` 汇总，每 50 ms 采样，包含独立分离实例的主进程、GPU、工具进程和渲染进程；不包含播放器主实例或 Vite。这是工作集计数对照，不是操作系统可用物理内存的下降量，也不是显存硬上限。单位为 MiB，1 MiB = 1,048,576 字节。

| 模型 | 优化前两轮峰值 | 优化后两轮峰值 | 平均峰值降幅 | 平均总耗时：前 → 后 |
| --- | --- | --- | --- | --- |
| HQ3 标准 | 1448.8 / 1505.3 | 1298.6 / 1327.1 | 11.1% | 21.18 s → 21.21 s |
| HQ3 半精度 | 1340.0 / 1384.7 | 1221.6 / 1202.2 | 11.0% | 17.15 s → 17.14 s |

两种模型各自的优化前后输出 SHA-256 均完全相同，输出长度均为 31,752,044 字节。本轮不改变模型选择或精度；半精度模型使用现有转换脚本在临时目录生成，仅用于比较，不代表验证了公开模型下载发布。

- HQ3 标准：`4995f9745243d0e4ac3b7de1913770587d8e66dcda8aa173ab7f5e2144241066`
- HQ3 半精度：`d75fb21a684704bc0f7cf53d6fc15d9c3c0d0a3ee24bd569a614a93e9f9f5456`

按数据尺寸计算，180 秒立体声避免了约 60.6 MiB 的整首 PCM 拷贝和约 30.3 MiB 的整首 WAV 缓冲。实际工作集差值还受到垃圾回收与进程分配的影响，不能把上述尺寸直接等同于进程峰值降幅。GPU 中间张量仍是大头，本轮没有降低或放宽资源准入预算。

原始分组结果见 [measurements.json](assets/2026-10-27-karaoke-memory/measurements.json)。其中 GPU 指标来自每 250 ms 采样的系统级 IOAccelerator 计数，含其他进程和驱动波动，不能与进程工作集相加，也不据此宣称本轮降低了 GPU 峰值。

## 未采用的策略

| 策略 | 本机结果与决定 |
| --- | --- |
| 关闭 GPU 缓冲缓存（`disabled`） | 标准及半精度均触发 `Buffer used in submit while destroyed` 校验错误，未采用；失败任务的低峰值不计为优化收益。 |
| 按精确尺寸缓存（`simple`） | 标准约 1459.7 MiB、半精度约 1375.4 MiB，没有稳定内存收益；保留 `lazyRelease`。 |
| GPU 输出绑定 | 进程峰值变化较小且 GPU 计数有波动，没有证实稳定收益，未采用。 |
| 降低图优化等级 | 进程峰值降低，但 GPU 计数升高且耗时增加，未采用。 |
| 显式关闭 CPU arena / memory pattern | 当前 WebGPU 路径下没有可复现收益，未额外加入设置。 |
| 缩短模型输入 | HQ3 的时间维度固定为 256 帧，不能直接缩短参数，未改动模型输入。 |

## 正确性与边界

- `npm run typecheck` 通过；全量 Vitest 为 365 个文件、3434 项测试通过。
- 分块 WAV 与原编码逐字节对照，覆盖空输入、整块和尾块；延迟写入时不继续推理，写入错误立即结束。
- 单声道左右缓冲独立；立体声转移原缓冲；文件上传完成、HTTP 失败及上传中取消后清理临时文件。
- Worker 推理、写入和关闭失败时中止写入并清理；正常返回文件前已关闭写入流，各块推理张量及时释放。
- 隔离的实际 Electron 辅助进程完成 3 秒音频生成、180 秒音频开始后取消、取消后再次生成。
- 实际 Electron 在拒绝页面权限的配置下，`http://` 和 `file://` 页面创建的内联 Blob Worker 均可写 OPFS、返回可读 File，并由页面删除临时输出。File 必须在上传完成后再删除，符合 [File System Standard](https://fs.spec.whatwg.org/#api-filesystemfilehandle-getfile) 的生命周期要求。
- 独立复核未发现阻断问题。Windows 实机及低磁盘空间的系统级故障仍待验证；空间/权限错误已有回归用例，实际写入错误会让任务失败。

输入仍使用整首解码，超长音频的 PCM 占用会随时长增长，沿用 128 MB 输入与 30 分钟时长上限。临时输出位于辅助进程资料目录，最终成品保存位置遵循原有设置。本轮未执行安装包构建。

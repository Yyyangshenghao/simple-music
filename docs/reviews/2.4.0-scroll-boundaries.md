# 2.4.0 间歇滚轮启停卡顿

目标 `dev/2.4.0`，基准 `eaf9ca0`。用户补充使用外接鼠标滚轮，刚开始或停止时顿一下。此前连续滚动采样不足以覆盖这种边界。

## 原因与改动

- 每次停止 180ms 后，静止光标下的悬停动画会重新启动；下次滚轮又暂停。间歇滚轮使整批卡片反复切换动效、创建/移除光斑。新增 `observeCardScrollActivity`，滚动结束后保持装饰暂停，等停止后的指针移动、按下或焦点进入才恢复。探索页和我的库启用；虚拟列表的查询恢复及默认 ScrollArea 继续使用原逻辑。
- 探索页滚动状态原来由页面持有，更新 AnimatePresence 后会通过布局上下文触发深层共享封面重新测量，绕过推荐区域的 memo。现在由私有包装组件持有状态，稳定 children；根标记与 context 仍通知卡片，平台和详情切换仍正常更新。
- 来源标识恢复时的 max-width、padding 过渡仍逐帧改变布局。只保留 opacity、transform 过渡，展开条件、常显、reveal 和触屏展示不变。

单独关闭背景或追光没有消除停止边界的长帧。保持光斑节点、重绑倾斜 MotionValue 的实验也未带来明确额外收益，未保留；不依赖 Motion 的内部 presenceAffectsLayout 属性。

## 同采样器对照

实际 macOS Electron 开发窗口 / Apple M5，1280×800、DPR 2、独立 userData。固定鼠标在网易云“我的歌单”轨道，10 次 wheel，每次 ±30px、间隔 450ms，每 5 次反向；预热后再次移动指针并等待，确保采样从正常悬停开始。账号/API 为测试资料，封面为本地 PNG。采样只计数，不逐次读取滚动布局。

| 指标 | 基准 | 修改后 |
|---|---:|---:|
| 停止窗口最大 rAF 间隔范围（wheel 后 150–300ms） | 11.6–23.5ms | 6.0–6.6ms |
| 整段大于 16ms 的 rAF 间隔 | 10 | 0 |
| 共享封面布局读取 | 80 | 0 |
| Layout 次数 / 累计 | 353 / 100.125ms | 3 / 1.266ms |
| 光斑新增 / 移除 | 100 / 100 | 0 / 10 |
| First scroll update 输入至呈现中位数 | 29.490ms | 24.052ms |

主线程间隔改善不能证明没有合成丢帧。PipelineReporter 的 STATE_DROPPED 仍为 72→68，不能从平均帧间隔宣称“完全不卡”。真实滚轮驱动、远程图片解码及用户播放状态还需实际使用反馈。GPU 列是进程 CPU 时间占墙钟时间的比值，不是硬件利用率。[完整结果](2.4.0-scroll-boundaries-verification.json)。

## 验证

- 新 helper 回归先失败，修复后间歇滚轮、停止后 pointermove/pointerdown/focusin、监听和计时器清理通过；ScrollArea 回归覆盖 opt-in 行为，虚拟列表恢复逻辑不变。徽标组件回归确认尺寸过渡断言先失败、修改后通过。
- `npm run typecheck`、277 文件 / 2,604 项测试通过，未做生产构建。
- 真探索页：停止保持暂停、主动移动恢复，滚轮后立即横向拖动跨越停止边界仍可继续（scrollLeft 60→260），不误开预览；暂停中点击、停止后同坐标按下、从外部移入和屏内焦点恢复通过。
- 网易云、QQ、Apple 平台切换通过；共享封面进入详情并返回，滚动位置 100→100。
- 我的库三平台 7 组歌单/收藏/专辑入口验证停止保持、主动恢复、暂停中点击和返回；偏好不变。
- 独立复核无阻断项。已查看[深色 1280 宽](assets/2.4.0-scroll-boundaries/dark.png)与[浅色 960 宽](assets/2.4.0-scroll-boundaries/light.png)，布局与操作入口正常；设计检测无新增报告。

# 2.4.0 歌单轨道动态来源标识滚动保护

目标 `dev/2.4.0`，基准 `33e25cd`。用户反馈探索页歌单轨道悬停滚动仍卡；标题同步从“你的歌单”改为“我的歌单”，包含轨道及浏览位置的可访问名称。

## 证据与修改

倾斜、光斑和辉光已在滚动期间暂停，但 `SourceBadge` 的 dynamic 模式仍响应 `button:hover`，通过 180ms 的 max-width、padding 过渡反复改变尺寸。单独取消该标识的过渡即可使布局次数从 82 次降到 6 次；暂停其展开后降到 2 次。本地 Motion 空 hover 目标核验没有动画或布局读取，不改动现有进出跟踪。

为悬停设备中的动态标识复用滚动标记，固定折叠尺寸并关闭过渡；停止后原有悬停展示恢复。规则同时覆盖普通和紧凑标识，以及只有探索页根标记、没有 TiltCard 的最近播放区域。常显、显式 reveal 和触屏常显标识不受影响，用户偏好保持原样。

## 采样

真实 macOS Electron 开发窗口 / Apple M5，1280×800、DPR 2，独立 userData 与网易云测试资料、本地 PNG 封面。先将账号歌单轨道滚到可见中部，鼠标固定在轨道内；60 次原生 wheel，每次 ±10px、间隔 16ms，每 15 次反向。前后均记录 60 个 wheel、60 个 scroll、28 个 pointerover，没有 pointermove。监听只计数，不在每次 scroll 中读取布局，避免采样本身强制同步布局。

| 样本 | 布局次数 | 布局累计耗时 |
|---|---:|---:|
| 基准 | 82 | 9.345ms |
| 最终 CSS 原采样器 | 3 | 0.899ms |
| 仓库聚焦采样器复核 | 1 | 0.555ms |

本次可确认的是重复布局减少。整体样式、绘制和 GPU 进程 CPU 时间有波动，不据此宣称所有卡顿已消除或 GPU 利用率降低。采样的 GPU 列是进程 CPU 时间与墙钟时间的比值；本地替代封面也不能覆盖真实图片解码或实体输入设备的全部表现。[机器结果](2.4.0-source-badge-scroll-verification.json)保留对照与最终采样。

## 验证

- 类型检查、277 个文件 / 2,601 项测试通过；标题与轨道名称加入既有首帧断言，独立复核无阻断项，未做生产构建。
- [实际组件回归](checks/explore-hover-scroll.cjs)新增动态标识断言，旧实现在暂停时仍为 max-width 160px / opacity 1，先失败；修复后普通、紧凑和最近播放标识暂停/恢复通过，常显、reveal、触屏展示以及原有倾斜、辉光、点击回归通过。
- 实际探索页验证暂停中标识无过渡、滚轮后立即横向拖动跨越停止边界仍可继续（scrollLeft 60→260）、拖动不误开预览、滚动中点击仍打开预览。
- 我的库网易云、QQ、Apple 共 7 组歌单/专辑/收藏入口的暂停、恢复、滚动中点击与返回回归通过。

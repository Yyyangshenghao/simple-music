## 问题与验收目标

### CR-01：更新下载文件写入错误（P1）

位置：`server/lib/update.ts` 的更新包下载循环。`createWriteStream` 创建后没有持续监听 `error`；等待网络下一块数据时，磁盘满、权限变化或文件无法打开会产生外层 `try/catch` 无法捕获的异步异常。下载在 Electron 主进程执行，可能影响整个应用。

审查复现：延迟上游响应并模拟目标无法打开，启动接口先返回 downloading，随后出现 `uncaughtException`（EISDIR）。验收：写入失败转为任务失败或既有线路降级，不出现未捕获异常；读取、写入和临时文件正确清理，正常下载及完整性校验保持通过。

### CR-02：音频中断泄露文件句柄（P2）

位置：`server/lib/audio-cache.ts` 的 `serveFileWithRange`。响应 `close` 只释放租约，未销毁源文件流。影响 `/api/local/audio`、离线文件及普通音频缓存命中；切歌或 seek 中断大文件传输时可能积累文件句柄。

审查复现：真实 HTTP 读取 8 MiB 文件，客户端收到首块后断开，源流仍未关闭且 fd 存在。验收：响应关闭销毁源流，完成回调仅执行一次；正常整文件、Range、错误响应仍有效。

### CR-03：Apple 旧播放覆盖暂停（P2）

位置：`server/lib/apple-music-web-page.ts` 的 play 命令。订阅检查返回后无条件清空 `pausedId`，可能覆盖检查等待期间新收到的 suspend；主进程后续 pause 必须等旧播放操作完成。

审查复现：订阅缓存超过五分钟，点击播放后在订阅检查返回前暂停，旧请求仍调用 SDK play。验收：后续暂停优先于旧请求；普通暂停后主动恢复可以起播，切歌、加载取消和控制序号仍正确。真实 Apple DRM 延迟需实机复核。

### CR-04：刷歌断点错误归属（P2）

位置：`src/lib/playback-persistence.ts` 的 `savePlayback`，关联 `src/stores/shuange.ts`。刷歌只更换 player 当前曲目，普通 playlist 保持原队列；持久化把刷歌的 position 写到原队列当前歌曲。

审查复现：普通歌曲 A 到 20 秒，刷歌曲目 B 到 95 秒后保存，恢复为 A 的 95 秒。验收：刷歌期间退出恢复原队列及进入刷歌前的正确断点；普通队列、空队列、随机顺序和断点恢复不退化。

### CR-05：Windows 轮询进程引用竞态（P2）

位置：`electron/platform/win32.ts` 的 mouse poller。停止旧进程后立即清空引用；重开歌词创建新进程后，旧进程迟到的 exit/error 无条件清空新引用，导致关闭时无法 kill 新进程。

审查复现：模拟 start/stop/start/旧 exit/stop，新进程未被终止，再开启创建第三个进程。验收：迟到回调只清理自身；旧 stdout 不触发新会话，中键轮询启动/停止可重复，需补 Windows 实机验证。

### CR-06：集合缓存键缺少类型（P2）

位置：`src/hooks/useLazyPlaylist.ts`。缓存只按 `source:id`，专辑与歌单可能同 ID；已加载的歌单会让专辑跳过加载并使用错误曲目。

审查复现：同网易 ID 的歌单返回 [11]，专辑应返回 [22]，实际专辑仍是 [11] 且专辑接口未调用。验收：类型不同的集合彼此隔离；hook、命令式加载、失效、TTL 与 LRU 使用一致的缓存身份。

### CR-07：推荐内容更新判断不完整（P2）

位置：`src/hooks/useLazyPlaylist.ts` 的 initialTracks 缓存播种。只比较数量和首尾，内部变化被忽略；refresh/checkForUpdates 又跳过已有 initialTracks 的集合。

审查复现：依次传 [1,2,3,4]、[1,3,2,4]，队列都返回 [1,2,3,4]。每日推荐与雷达有真实传入路径。验收：中间换歌和重排反映到详情与播放队列，更新曲目资料不会继续显示旧详情，反复渲染不产生额外上游请求。

# 2.4.1 Folium 歌词模组市场（首版）

目标分支：`feature/folium-lyrics-market`（基于 `dev/2.4.1`）。方案见 [2026-10-21-folium-lyrics-market](../plans/2026-10-21-folium-lyrics-market.md)。内置跃字保留为默认样式和失败兜底，逐字歌词补全是内置样式与模组共用的数据来源。

## 行为

- 歌词页新增「模组」侧栏，分为可用、已安装和全部三类。不兼容的模组会显示原因：先行测试版、需要主进程扩展、尚未适配宿主能力或新版本尚未验证。
- 安装后不会切换当前样式。点「试用」只临时生效；点「结束试用」回到原样式；点「使用」才写入 `simplemusic-lyric-mods`；点内置「跃字」取消模组选择。
- 模组在 `simplemusic-mod://` 沙箱 iframe 中运行，只接收歌词投影、主题、显示配置以及节流后的时钟和频谱。关闭歌词页即移除 iframe；暂停或页面隐藏时停止帧循环。
- 以下情况都回到内置跃字：启动超时、运行时未捕获异常、本地文件校验失败。前两种提供重试；文件异常时卡片提示卸载后重新安装。

## 验证

- **自动化**：类型检查通过，全量 316 个文件、2966 项测试通过；本轮新增非阻塞加载、嵌套框架拒绝和设置项整理的用例。
- **真实市场**（2026-10-21）：目录共 27 个模组，其中 3 个通过兼容验证。虹光 `sample-aurora-visualizer` 1.0.1、52Hz `visualizer52hz` 1.0.1 和巨幕 `cinerama` 1.0.0 都能完成下载、SHA-256 与 Ed25519 校验、加载和卸载；其余 24 个显示不可用原因。
- **macOS Electron 隔离实例**（独立 userData、自制歌词、无真实账号与音频）：
  - 三个模组都能挂载，拖动进度和切换深浅主题时同步，无页面异常。
  - 试用、结束试用、使用后持久化、切回内置跃字、关闭歌词页后移除 iframe，均符合预期。
  - 960×720 窄窗口下侧栏不遮挡模式切换和播放条。
  - 篡改已安装包后，回到内置跃字，并标记「文件异常」。
- **沙箱实测**：在模组 iframe 内发起以下操作，全部失败：访问外网、访问应用页面、访问其他模组的资源、加载外部图片、读取父窗口 `desktop`、读取 `top.location`、`window.open`。嵌套框架的加载以 `ERR_BLOCKED_BY_CSP` 被拒。

## 独立复核

没有高危问题。处理结果：

- **已修**：
  - 安装期间已安装模组的资源请求被串行锁卡住，会导致启动超时。现在加载不再等待锁。
  - 子框架导航守卫没有限定在主窗口的直接子框架。已加上层级判断；CSP 已实测会拦截嵌套框架。
  - 模组的任何 `console.error` 都会被当成失败并退回内置样式。现在只有未捕获异常才算失败。
  - iframe 发来的设置项在主窗口没有二次整理。已补上校验。
  - 市场请求改用 `net.fetch`，以遵循系统代理。
- **保留**：每次打开歌词页都会在主进程同步重新校验全部已安装包。三个包的耗时很短，以后模组增多时再按 mtime 和 size 缓存。

## 已知限制

- 巨幕会自己绘制译文，同时宿主仍显示底部字幕。打开模组侧栏时，内置跃字不会让位，部分歌词会被侧栏遮挡。
- 只在 macOS 上实机验收，Windows 和 Linux 未验证。

# 2.3.3 设置页闪烁修正验收

目标分支：`dev/2.3.3`，基于已发布的 `v2.3.2`（`34c6312`）。
对应问题：[Issue #31](https://github.com/Yyyangshenghao/simple-music/issues/31)。

## 报告与判断边界

报告称鼠标在底部播放栏移动时，设置页面底部 UI 闪烁；截图是 Windows 窗口，标注区域位于设置卡片的滚动裁剪边缘。报告未给出系统版本、GPU 或动效配置。本机 macOS 未稳定复现该闪烁，不能把本机检查通过视为 Windows 根因已确认。

修改前实际计算样式显示，设置网格入场结束后仍保持 `transform: matrix(1, 0, 0, 1, 0, 0)`，卡片独立使用 `backdrop-filter: blur(12px)`。全屏流体背景响应鼠标，播放栏也有玻璃层与按钮悬停重绘，因此本轮针对滚动边缘的独立合成及背景重采样通路做局部规避。

## 改动

- 设置网格的入场动画改为 `backwards`，结束后恢复普通绘制状态；时长、曲线和淡入位移保持原值。
- 设置页普通卡片、桌面歌词设置卡片、快捷键卡片统一取消背景模糊，保留半透明底色、主题边框、阴影与布局。
- 存储卡片原有的专用取消模糊规则并入统一策略。设置说明浮层仍保留自身背景模糊及激活层级。

## 已完成验证

- `npm run typecheck` 通过。
- `npm test`：196 个文件、1620 项通过。首次受限环境无法监听临时 HTTP 服务，正常本地权限重跑通过。
- 隔离数据的 macOS `npm run dev`：深浅主题的界面设置、歌词卡片、说明浮层、快捷键与关于应用滚动区域可正常显示；播放栏交界没有观察到稳定的异常闪烁。
- 本地页面运行时检查：全部设置卡片的背景模糊为 `none`，5 个设置/歌词网格结束后 `transform: none`、`opacity: 1`。
- 本地浏览器按报告尺寸 1444 × 813 检查侧栏布局，并在 900 × 700 检查单列布局，未见布局回归。浏览器不替代 Electron/Windows GPU 验证。
- 独立复审未发现明确回归；再次指出 Windows 原环境验证仍缺失。

## Windows 发布验收仍待完成

在 `dev/2.3.3` 使用与报告相同的 Windows 设备及配置：

1. 打开设置，滚动到“界面与窗口”，让卡片被内容区域底边裁剪。
2. 持续播放和暂停两种状态下，反复移动鼠标经过播放、音量、队列及更多按钮，检查底部是否还有亮条、缺块或闪烁。
3. 覆盖深浅主题、标准/简单/极简动效，检查歌词、缓存、快捷键卡片和说明浮层。

确认上述原场景通过后，才能判定 #31 完成并准备正式发布。本轮不关闭 Issue、不打正式 tag；应用版本号仍为已发布的 2.3.2，2.3.3 版本号及发行说明在发布元数据提交中统一更新。

## 依赖审计评估

`npm audit --omit=dev` 报告 14 项生产依赖风险：3 项中等、10 项高、1 项严重。按本应用的实际调用路径逐项评估后，本版只处理一项。

- **已修复：`music-metadata`（高）。** `server/lib/local-library.ts` 用 `parseFile` 读取用户本地音频；构造的畸形文件可让解析陷入死循环或无界分配，而 API server 内嵌在主进程，会卡死整个应用。已在原版本范围内升至 `11.16.1`（锁文件另随之把其子依赖 `content-type` 升至 `2.1.0`），未改动其他依赖。
- **暂缓：其余 13 项均经 `NeteaseCloudMusicApi@4.32.0` 引入。**
  - `proxy-addr`（严重）、`express`、`body-parser`、`qs`：本应用只按函数库调用网易接口，不启动其自带的 express 服务；自有 server 为 Node `http`，只监听 `127.0.0.1`，这些模块不在请求路径上。
  - `pac-proxy-agent`、`get-uri`、`basic-ftp`、`ip-address`：仅在为网易请求配置代理时使用，`server/lib/netease-client.ts` 未传代理参数。
  - `axios`、`follow-redirects`、`node-forge`：仅在网易包内部构造的出站请求与加密中使用，输入不来自外部请求。
  - 网易包内嵌的 `music-metadata@7.14.0` 不被本应用调用。
- 审计给出的自动修复是把 `NeteaseCloudMusicApi` 降至 3.x 主版本，不采纳。待上游发布修复版本后再随版本升级处理。

升级后的验证：类型检查通过；本地音乐相关 23 项测试通过；全量 350 个文件、3,344 项测试通过；`npm run build` 通过；用新版对真实 MP3、FLAC、M4A 文件解析，标题与时长读取正确。

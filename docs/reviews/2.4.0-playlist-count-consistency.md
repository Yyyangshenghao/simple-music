# 2.4.0 歌单数量一致性与同步测试验收

2026-10-18，基准 `ae1edd0`，目标 `dev/2.4.0`。本阶段回应「同步用例覆盖是否充分」与「我的库卡片数量和详情不同」；沿用既有双向同步实现，没有重做已验收功能。

## 数量差异的真实证据

卡片原先直接显示平台歌单摘要 `trackCount`；详情按读取到的有序歌曲 ID 列表计数，详情缺项不会缩短列表，也不按是否可播放筛选。因此两处并非同一个统计来源。

使用当前保存会话只读核对两份网易云歌单，输出仅保留匿名统计，没有账号、原歌单名称/ID或凭据：

| 样本 | 平台卡片/详情摘要 | 完整 ID 数 | 普通条目 | 私人云盘条目 |
|---|---:|---:|---:|---:|
| 1 | 864 | 870 | 864 | 6 |
| 2 | 862 | 868 | 862 | 6 |

6首均带云盘元信息，并能在该账号云盘列表中匹配；普通条目数量恰好等于摘要。这两份的差额对应云盘统计口径，不能归因为版权删除。两份各有14条播放权限受限记录，数量也不是6。会员付费标记同样不等于不可播放，不能拿它减总数。

QQ另外只读抽查两份，卡片摘要、详情摘要、返回 ID 数和返回歌曲数分别均为162与4，当前样本未重现数量差异。这里不能推导所有 QQ 歌单都一致。

证据：[网易云匿名统计](assets/playlist-count-consistency/netease-readonly-counts.json)、[QQ匿名统计](assets/playlist-count-consistency/qq-readonly-counts.json)。本轮真实账号写入为0，没有修改原有歌单。

## 修改后的口径

- 未读取详情的在线歌单卡片明确显示“平台统计 N 首”，未知数量沿用“查看歌曲”。本地、专辑及调用方显式传入的辅助信息沿用原行为。
- 读取详情后返回卡片，复用实际读取的有序 ID 位置数，空列表显示0；不按详情加载数量、可播状态或唯一 ID 数计数。
- 不为卡片单独拉详情，沿用现有最多4份、10分钟的有界缓存。来源、实体类型、账号会话及 QQ 红心版本隔离；过期、失效、失败或新摘要变化时不冒用旧值。卡片返回或重渲染时读取，未新增所有预览卡片的实时订阅。
- QQ此前按“名称且MID”过滤，只有名称缺失也会少计；现在有 MID 就保留，以身份占位标题显示，版权/会员和合法重复位置继续保留。
- QQ浏览允许“摘要偏大但明确结束”以及“摘要偏大、无标记的空终页”，展示可读取歌曲。空页仍显式声明有下一页、分页间总数突变、分页上限仍有更多时不伪装成功；不按摘要捏造歌曲身份。缺 MID 的隐藏歌曲仍无法恢复。
- 同步更新采用独立的严格快照读取，不因上述浏览兼容而放宽删除差集保护。

## 验证

新增46项自动化：同步23项、QQ读取14项、数量缓存6项、卡片3项。同步6个文件共239项通过，其中3项合并用例另执行422组固定输入组合；完整范围、各层断言和外部限制见 [同步测试矩阵](2.4.0-playlist-sync-test-matrix.md)。没有发现需要修改同步源码的问题。

全仓 `npm run typecheck` 和 `npm test` 通过：271个测试文件、2660项测试。数量覆盖云盘870/864、详情少返、不可播保留、重复位置、空列表、账户切换、平台停用、过期/失败/淘汰、摘要变化及类型/来源隔离。QQ读取文件96项通过，包括明确/无标记终页与分页边界。卡片设计检查无发现；没有执行安装包构建。

通过 `npm run dev` 启动独立 Electron 开发窗口和隔离存档，使用合成平台响应，网易云及QQ歌曲读取经过真实本地 HTTP 路由与映射。验证：

1. 打开库时显示“平台统计864首”，不逐卡请求详情。
2. 网易云完整870个身份、其中详情少返，标题仍870；返回卡片870，库清单仅请求一次。
3. 空列表0替代旧摘要2。
4. QQ摘要4、实际3，明确终页仍可打开；缺名 MID 与会员曲目均保留，返回卡片3。
5. 深色1536×864、浅色960×540；卡片和详情无横向溢出，页面错误0。

## 真实边界

平台完全不返回身份的曲目无法补回；已读取数量表示当前缓存中的列表，不是云端永久实时数量。本轮未尝试改变版权播放限制，也未在真实账号制造限流或反复写入。跨设备同时写入、地区和权益差异、平台协议后续变化及 Windows/Linux 实机仍不属于穷尽验证；双向同步平台非原子、进程检查点和 QQ 顺序限制详见测试矩阵。

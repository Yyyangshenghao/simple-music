# 2.4.0 QQ 账号与推荐能力补强

目标 `dev/2.4.0`，功能分支 `feature/qq-platform-parity`。新增真实日推、账号最近歌曲与红心交互，保留既有应用歌单同步范围，不升级版本或发布。

本记录保存提交85065b9时的验收边界。后续已修复红心签名加密协议并完成真实添加/取消及实际按钮验证，原歌单全部恢复，见 [后续修复验收](2.4.0-qq-favorite-protocol.md)。下文的红心未验证描述仅指此前阶段。

## 完成行为

- 探索增加原生“每日30首”，与“猜你喜欢”分开。动态发现日推歌单，按上海当日核验；缓存跨日失效，旧日迟到响应丢弃，只刷新日推，不重置牌堆。刷歌继续优先连续流，保留网易日推回退。
- QQ账号“最近听过”显示最近20首，可点击播放；与本机最近记录分开，空数据隐藏，失败提供重试。上游请求窗口2500，不承诺完整历史；漫游和刷歌取前100首作为口味种子，不伪装周听歌排行。漫游已加载及在途建议按账号epoch失效。
- QQ红心按MID批查，最多100首一批。写入带账号会话，按MID核实数字ID和真实类型、同曲串行，写后确认才成功。失败回滚并提示，80105不使账号过期，明确鉴权错误才触发重新登录。
- QQ写成功版本由后台快照投影到UI，库/探索账号歌单使用新缓存键，我喜欢详情/预览/快捷播放重新读取；查询、乐观更新或失败不触发刷新，普通歌单继续复用缓存。原有滚动防请求风暴保护保持生效。

## 真实验证与限制

使用当前开发进程同一QQ登录态、独立本地HTTP服务验证新增路由，未重启用户播放器。真实读取最近413首与日推30首，均返回200、QQ来源与歌曲身份完整、MID唯一；批量红心返回完整boolean状态。原始响应与私人曲目不落库。

用户另外允许一次“添加后还原”。仅选择原本未收藏的一首公开测试歌曲，网络保护只允许该歌曲进入201目录，一次Add上限，拒绝其他目录和曲目。真实添加返回80105、未生效，未执行撤销或第二次添加；测试歌曲仍未收藏，原有5份歌单目录、全部可读曲目身份和顺序摘要一致，原收藏162首。最终写参数随后按官网移除tid/bFmtUtf8，只做模拟验证；真实添加/撤销成功仍是缺口，不能宣称当前账号已可写红心。

精确歌曲排序、账号最近歌单、独立周听歌排行未核实。排序仅有第三方审计中的SeqSonglist方法名，缺少调用契约，不猜参数，不删光重加模拟排序。新版官网公开脚本下载曾被自动审批以用量限制拒绝，未执行；已用其他公开源码继续研究，未绕过审批。

## 验收

- `npm run typecheck`通过；全量Vitest **267文件、2451项通过**。覆盖路由错误契约、跨日/换号/取消、曲目身份、批次上限、写锁、状态幂等、失败回滚和缓存刷新、QQ连续流与最近种子、网易/本地回归。
- macOS实际Electron开发窗口、独立userData、所有账号写请求模拟。10项交互检查通过：原生栏目分离、最近歌曲、请求共用、后台红心版本刷新库、已打开我喜欢详情自动刷新、80105回滚提示、最近失败重试、浅色最小窗口、换号重查、受控上海午夜只刷新日推。无pageerror。
- 独立上下文复核关闭最近吞错、固定日推误用为连续流、红心鉴权错误未转换问题；最后复核漫游账号隔离，无剩余新增P1/P2。
- 没有验证Windows/Linux实机、QQ真实红心撤销成功、完整历史或周统计，也没有宣称精确排序支持。机器记录见 [验收数据](2.4.0-qq-platform-parity-verification.json)。

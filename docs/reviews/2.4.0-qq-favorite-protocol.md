# 2.4.0 QQ 红心签名加密协议修复

目标 `dev/2.4.0`，分支 `feature/qq-favorite-protocol`，基准85065b9。用户继续授权QQ账号测试，保留此前不修改原有歌单的要求。

## 根因与改动

红心201目录使用明文musicu通道时返回80105。官网param修正、数字uin及去除authst均未解决；同账号同测试歌曲切换官网zzc签名+ag-1加密musics通道后，Add/Del各层码及读回状态均成功。普通歌单此前已验证的通道继续使用，只分流201的AddSonglist/DelSonglist。

协议根据MIT授权qmweb-sign固定源码实现，使用Node内置crypto，不新增依赖。签名与加密使用同一JSON，每请求随机96-bit IV、AES-128-GCM，固定HTTPS端点，禁止重定向带出Cookie；超时不重发、不回退明文，仍由路由核实账号会话、曲目身份和最终收藏状态。

写入响应的文字字段实测含不规范UTF-8字节，fatal文本解码导致已生效写入误报失败；对照协议默认TextDecoder后，JSON、业务码和retCode继续严格检查。2000是签名要求，收藏、账号数据及我喜欢读取不再将其误判为登录过期；301/1000仍归鉴权。

## 真实测试

每轮先核对当前开发进程与保存账号一致，读取原有5份目录和全部可读有序曲目摘要。网络层仅允许一首原本未收藏的公开测试曲进入201目录，一轮最多一次Add，取消只能作用于该测试曲；不删除或重排原有歌曲。最终每轮原目录、身份与顺序摘要均恢复一致，收藏仍162首。

正式源代码本地API的添加和取消均 `success:true`，IsSongFanByMid分别确认true/false；没有覆盖请求传输。随后在实际macOS Electron隔离窗口点击播放栏红心，放行真实session/check/like API，其余窗口数据用隔离占位，避免展示私人歌单。真实添加、取消、后台成功版本递增、UI红心变化均通过，无pageerror。测试账号凭证只由独立服务内存读取，没有复制到测试窗口资料目录。

诊断期间两轮签名写入因fatal响应解码误报失败，但finally通过真实状态发现并取消了测试收藏；快照均已恢复。改为协议默认解码后完成完整原型、正式路由和实际按钮成功验证。没有把接口接收、乐观红心或HTTP200单独当作成功证据。

## 回归与复核

- 先写201写通道回归，旧实现6项失败，修复后通过。
- 已知上游签名/响应向量、同JSON签名加密、随机IV、非法JSON、非标准文字、HTTP失败、超时不重发、普通歌单/读取不切换通道均有覆盖。
- `npm run typecheck`通过；全量 **269文件2468项通过**。
- 独立只读复核8文件253项、最后错误归类3文件165项通过，无新增中高风险。
- 开发窗口构建产物确认保留完整MIT许可。未构建安装包、未验证Windows/Linux实机。精确排序、账号最近歌单、周排行仍是前阶段已有缺口，未扩展能力。

机器记录见 [脱敏验证数据](2.4.0-qq-favorite-protocol-verification.json)。协议来源及固定提交见 [QQ API §2.8](../qq-music-api.md#28-2026-10-16-红心签名加密协议修复)。

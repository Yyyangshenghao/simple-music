# 2.4.0 网易云探索页滚动合成优化

目标 `dev/2.4.0`，基准 `c84e9f8`；工作分支 `feature/explore-scroll-performance`。不升级版本或发布。

## 问题与修改

探索页主要由封面、推荐面板和榜单组成，不走歌曲虚拟列表的渲染路径。排查确认两类额外成本：长推荐面板及嵌入榜单重复执行背景模糊；闲置卡片仍保留透视、`preserve-3d` 与极小 Z 轴位移。CDP `LayerTree.compositingReasons` 显示，卡片的 BorderGlow 和 spotlight 会作为 `Leaf of a 3D scene` 单独合成。

推荐面板保留现有着色背景，去掉整块长内容的模糊；榜单仅在探索页嵌入模式取消内层模糊，独立榜单页不变。共享 TiltCard 在角度归零时将透视设为 0，回弹尚未结束时保持透视；移除无实际 Z 轴分层用途的 `preserve-3d` 及 BorderGlow 常驻微小位移。卡片整体倾斜、光斑、辉光、按压及共享封面转场继续使用现有实现，顶栏与播放栏的模糊不变。全宽布局下榜单的模糊质感也相应减少。

本地 Motion 实现已核对：数值 0 的透视不进入 transform，归零输出 `none`；弹簧完成时精确写回目标。额外的派生 MotionValue 不经过 React state，不引入逐帧组件渲染。

## 实测

真实 macOS Electron 开发窗口、Apple M5 / ANGLE Metal、独立 userData；网易云测试账号资料，8 张账号歌单、12 张最近歌单、4 张榜单及推荐封面。图片由本地 PNG 响应替代，动态背景、倾斜和光斑开启。视口 **1512×982、DPR 2**，鼠标停在内容中，发送 160 次原生 wheel，每次 ±25px、间隔 16ms，每 40 次反向。未做 CPU 限速。

| 指标 | 修改前一轮 | 修改后三轮 |
|---|---:|---:|
| 观测到的合成层数 | 58 | 23 / 23 / 23 |
| 超过 25ms 的帧间隔 | 2 | 0 / 0 / 0 |
| 帧间隔 P95 | 6.40ms | 6.30 / 6.30 / 6.30ms |
| GPU 进程 CPU 时间 / 墙钟时间 | 55.34% | 47.50 / 45.81 / 46.98% |

前后保留相同像素密度、操作序列和测试资料，测量中不截屏；截图通过 CDP 捕获，避免截图工具覆盖设备仿真参数。单独关闭内容模糊及 3D 的对照也记录在[机器结果](2.4.0-explore-scroll-performance-verification.json)中。

合成层减少是可重复的结构改善；一次基准中的偶发慢帧不足以宣称所有卡顿已经消除。GPU 进程的 CPU 时间不是 GPU 硬件利用率。原生 wheel 自动输入也不等于实体触控板惯性；真实账号的大封面下载、解码和后台播放仍需对应场景确认。

## 验证

- 闲置透视 SSR 用例在旧实现先失败，修改后通过；全量类型检查、276 个文件 / 2,596 项测试及独立复核通过，未执行生产构建。
- [实际卡片回归脚本](checks/idle-card-compositing.cjs)验证：初始 `transform:none`、平面子树、悬停透视与边缘辉光、回弹后释放、点击、倾斜/光斑独立选择、系统减少动态。
- 实际探索页检查深浅主题、限宽/全宽布局、1512×982 与 960×600；验证底部可达、推荐封面进详情再返回、横向拖动及歌单预览，无页面异常。测试资料的 API 与图片响应在整个交互检查期间保持隔离。

| ID与完整性 | 来源、ID、QQ数字身份/类型、重复MID/数字身份、缺页、错误总数、错误归属均在不可信删除前拒绝 | 两平台路由、客户端、存档；补充QQ分页中途总数/重复/身份坏值 |
| 版权及元信息缺项 | 完整引用仍在时，不以播放权限字段或详情返回数量过滤歌单；不可播曲保留；详情少返的有效ID用占位保留，不误入删除差集 | 补充两平台路由与两平台客户端 |

版权字段测试验证的是「身份关系不因不可播放或详情缺项丢失」。它不会将受限歌曲变得可播放，也不能恢复平台未返回任何身份的隐藏歌曲。歌曲数量口径由本阶段另外核对，不能只凭数量不等就判定为版权过滤。

## 仍然不能声称已覆盖的情况

- 平台没有原子条件写接口。写入前版本相同后，另一客户端在写入过程中同时修改，仍可能竞争；本地测试与既有真实验收不能给出事务保证。
- 网络/限流/实际版权拒绝的组合有无限多种。本轮用受控失败、静默漏歌和详情缺项验证恢复行为，没有反复请求真实平台制造限流，也未收集每个地区或账号权益的版权样本。
- 检查点仅在服务进程内保留且有容量上限。进程退出或检查点被淘汰后，首次创建成功但回执完全丢失的极端情形不能保证自动找回原目标；不冒险按名称绑定任意已有歌单。
- Windows/Linux实机、跨设备并发修改及平台后续协议变化仍需对应环境验证。QQ仍不支持推送歌曲顺序。

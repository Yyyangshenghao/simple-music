# B 站跨平台候选探测与确认

日期：2026-11-07。目标版本：`dev/2.7.0`；工作分支：`feature/bilibili-candidate-probing`。按维护者本轮明确授权，以本地 Squash 方式集成到 `dev/2.7.0`；不推送、不发布，原有未跟踪临时文件保留。

以下为首轮记录；平台参与规则已由文末“系统固定游客通道”调整替代。

## 行为

- 在设置允许的可用平台间并行探测，组合词不足时按可能的歌名继续搜索；每平台最多四词、每词前二十项、4.5 秒预算。跨平台统一评分，不再采用首个平台的首个可靠结果；复用已探测候选取歌词。
- 高置信度自动采用；有歧义时在“选择歌词”里展示最多三个不同录音，跨平台副本与重复发行合并。同分优先有封面的结果。
- 自动匹配仍遵守歌名、完整艺人署名、版本、时长与 ISRC 约束。人工候选允许时长差不超过视频的 10% 且最多 30 秒，分数随差值降低，最高 79 分；不会自动采用，也不会放宽录音版本冲突。
- 确认只接受宿主在当前视频、平台及账号上下文实际提供过的候选；回传元数据不作为可信来源。确认身份持久化并共享给歌名、歌手、封面与歌词，音频及实际视频时长保留。停用原平台或刷新候选不覆盖人工确认的歌手。
- 确认后终止旧歌词会话并重取，歌词预取键包含歌曲身份；切歌后的候选查询会取消，旧确认不能应用到新曲。部分探测失败不作为未收录复用，重新查找绕过负缓存。

## 实际运行与界面

使用 `npm run dev` 启动 Electron，采用 `/tmp/simplemusic-bilibili-probe-profile` 隔离数据目录。

真实接口样例：获取公开视频 `BV1GJ411x7h7`，原题为“【官方 MV】Never Gonna Give You Up - Rick Astley”，视频时长 213 秒；识别到网易云歌曲“Never Gonna Give You Up”／Rick Astley，匹配分 100，曲库提供专辑封面。此样例不代表总体识别率。

候选与确认界面使用拦截 API 的模拟歌曲数据，经真实宿主命令及 React 组件验收：显示三首同名异歌手、长署名省略、深浅主题、1440×900 与 960×540、悬停与点击确认。确认后宿主保存所选 ID 和人工确认标记，正式歌词更新为模拟响应正文；未播放视频音频。首次检查发现候选区内层滚动裁掉第三项，已去掉内层限高并复验，内容区统一滚动，底部操作保留在窗口内。

## 系统固定游客通道

维护者进一步明确：B 站专辑与歌词匹配不依赖用户启用或登录哪些其他平台，系统直接以游客查询。

- 歌曲身份固定探测网易、QQ 游客曲库；缓存、候选确认和封面请求键不再包含账号与平台开关。
- B 站网易/QQ 原生歌词与手动搜索都强制游客，不读取账号 Cookie；即使歌词平台和游客开关全部关闭也可查询。系统游客不受通用账号来源熔断影响，也不改写账号健康状态。
- 无自定义来源顺序时同样走系统游客串行查询。自动来源仅采用网易、QQ、AMLL、酷狗；AMLL/酷狗各自的歌词偏好开关保留。显式手选 Apple 的账号边界保留，其他来源歌曲规则保留。
- 无关账号与音源开关变化不取消或重发 B 站游客查询；用户切歌仍取消旧请求。

真实 Electron 验证采用隔离数据目录：将所有播放平台、歌词平台和游客开关全部关闭，AMLL/酷狗也关闭，再获取公开视频 `BV1GJ411x7h7`。后台自动识别出 Rick Astley 的规范歌名和专辑封面，网易云原生歌词返回 28 行。观察到网易/QQ 搜索及网易歌词请求均带 `guest=1`；打开“选择歌词”时网易、QQ 可用，其他已关闭来源保持关闭。此轮未播放音频，也未改布局。

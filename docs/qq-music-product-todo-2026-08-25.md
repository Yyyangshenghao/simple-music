# QQ 音乐板块下一轮需求 TODO（2026-08-25）

> 状态：本轮 P0、QQ-05～QQ-06 与 QQ-08～QQ-09 已实现；QQ-07 在测试账号验证中被上游拒绝（业务码 80105），尚未开放写入。本文基于当前代码、[QQ 音乐 API 梳理](./qq-music-api.md)及 2026-08-24 起的真实请求结果编写。

## 1. 结论

下一轮目标不是增加更多孤立入口，而是让 QQ 音乐形成完整的“发现 → 搜索 → 打开详情 → 收藏回访”路径。

建议本轮只做四项：

1. 升级正式歌曲搜索，移除 smartbox + 逐首补详情的旧链路。
2. 增加 QQ 音乐排行榜，复用现有榜单页面与卡片。
3. 补齐“我喜欢的音乐”只读入口，让“我的库 → 收藏”不再缺一块。
4. 统一 QQ 的歌曲、歌手和歌单标识规则，作为前三项的正确性前置条件。

写入“我喜欢”、创建歌单等账号写操作不进入本轮；必须先用专用测试账号完成副作用验证。

## 6. 明确延期或不做

- 新版歌手主页 `UnifiedHomepage/GetHomepageHeader`：当前 Web 信封实测返回 `code:10000`，不接入 Android session/QIMEI 体系。
- 独立 QQ 扫码 API：现有 Electron 官方登录页已支持二维码并自动捕获 Cookie，暂无重复建设价值。
- 推荐新歌独立栏目：与榜单和现有推荐内容重叠，先观察排行榜使用情况。
- 歌曲评论页：服务端已有评论路由，但当前没有歌曲详情产品入口；不为单一能力新建页面。
- MV：当前没有 MV 播放能力，不纳入 QQ 板块迭代。

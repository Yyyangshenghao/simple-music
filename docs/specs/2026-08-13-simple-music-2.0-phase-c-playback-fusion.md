# Simple Music 2.0 阶段 C：播放融合实现记录

> 日期：2026-08-13
> 分支：`codex/dev/2.0.0`
> 状态：实现完成，真实双账号播放矩阵待验收

## 1. 本阶段目标

把阶段 B.1 已建立的“登录且明确启用才参与”边界延伸到真正的播放链路。播放器不再只做“原平台失败后尝试一个对侧平台”，而是为每次播放创建独立、可取消、有限次数的解析会话：

1. 按一次性手动软优先、原来源优先和全局播放顺序生成候选平台。
2. 在目标平台保守匹配同一首歌。
3. 依次尝试同平台的音质和地址候选。
4. URL 非空但媒体加载失败时继续当前会话，而不是永久停在 loading。
5. 候选真正进入 `canplay` 后，才提交实际播放来源和实际曲目；缓存键始终按当前实际候选生成。

本阶段不实现硬锁音源、不自动跳过最终失败的歌曲，也不接入第三个平台。

## 2. 播放会话与状态边界

`PlaybackResolver` 是单曲单会话对象，保存来源顺序、匹配结果、音质游标、地址队列、已尝试 URL 和诊断尝试记录。所有搜索与 URL 解析共用一个 `AbortSignal`，切歌、手动重选音源或重载音质会终止旧会话。

播放器保留两组明确不同的数据：

- `currentTrack`：用户正在看的内容曲目，决定标题、封面、红心和原歌单语境。
- `resolvedTrack` / `actualSource` / `resolution`：真正交付音频的曲目、平台和解析结果。

只有媒体进入 `canplay` 后才设置 `actualSource`。加载中的候选不会被误报成实际音源；媒体 `error` 会记录为 `media-load:error` 并继续下一候选。最终候选耗尽后清空引擎地址并进入 `idle`，不会无限重试。

## 3. 来源顺序

每次会话按以下顺序去重并过滤非参与平台：

1. 用户在播放菜单选择的“本次优先使用 X”。
2. `preferOriginSource=true` 时的内容来源。
3. `playbackOrder` 中的其余平台。
4. `preferOriginSource=false` 且全局顺序没有内容来源时，内容来源补在末尾。

`multiSourceFallback=false` 时只保留最终顺序中的第一个平台。平台在请求途中被停用或登录失效时，迟到响应被丢弃，播放器以剩余参与平台重建会话。

## 4. 同曲匹配与缓存

当前保守匹配规则：

- Unicode NFKC、大小写、全半角括号、标点和空白归一化。
- 标题基础部分、主要艺人、版本标签和 3000ms 时长硬约束；艺人名末尾的括注别名不参与比较。
- ISRC、完整标题、主要/参与艺人、时长与专辑名加权评分。
- 自动匹配阈值 80 分；同名翻唱、Live、伴奏、Remix 等存在冲突时拒绝自动播放。

缓存键为 `originSource:originId -> targetSource`，schema 为 2，保存目标 ID、分数和去除临时 URL 的曲目快照。成功命中保存 30 天，未命中负缓存 24 小时；schema 2 会使旧版负缓存失效，以便按新的艺人别名规则重新搜索。网易云可在缺少快照时按 ID 补详情，QQ 则使用快照避免其旧服务不支持按 ID 补单曲导致缓存失效。用户永久确认和清除单条错误映射仍属于后续 2.x 延期项。

## 5. 同平台候选与媒体错误

- QQ 服务端现在按请求音质顺序返回所有有 `purl` 的文件，并为每个文件展开多个 `sip` 地址；播放器逐个尝试。
- 网易云现有接口仍先在服务端完成一次音质降级；若该地址发生媒体错误，解析器再读取该曲实际可用音质并逐档解析。
- 实际 URL 候选总尝试数默认最多 24 次；匹配和解析诊断不占用 URL 配额，同一会话不会重复相同 URL。
- 试听地址和自带直链不写磁盘缓存；正常候选用实际 `source:id:quality` 分键。server 仍只在完整音频流成功转发结束后原子提交缓存文件。
- 切换候选保留当前播放进度；外部直链和相邻曲目预解析命中也纳入同一错误回流链路。
- “本次优先”会绕过原平台的预解析捷径，确保目标平台真正排在首位；暂停态重建会话只预载不自动恢复播放。

## 6. 账号、歌词与界面语义

- 听歌记录上报 `resolvedTrack` 的平台和 ID；跨平台播放时不把原平台歌单 ID 发送给实际平台。
- 歌词先读取内容来源，内容来源不可用或无歌词时，再尝试当前实际解析曲目。
- 播放菜单同时展示“内容来自”和“实际播放”，并提供“本次优先 X”的软优先按钮。
- 播放栏来源徽标遵守常显/动态/隐藏：动态模式只在实际来源与内容来源不同时显示。
- 未参与平台不会出现在软优先按钮、候选链或实际来源标识中。

## 7. 自动验证

已覆盖：

- 来源顺序的手动软优先、原源优先、全局顺序和关闭跨源降级组合。
- 同名异歌、版本冲突、多艺人、缺时长、ISRC、阈值和正/负缓存。
- 同平台多地址、媒体失败、逐档降质、跨平台、最大尝试数和会话取消。
- 平台在请求前或请求途中失效时不再产出候选。
- `canplay` 才提交实际来源，媒体错误码能回流。
- QQ 多音质文件和多个 `sip` 的确定性候选顺序。
- 播放持久化恢复时不恢复过期的实际解析状态。

当前自动检查结果：类型检查通过；完整测试在允许本地回环端口的环境运行，47 个测试文件、381 个测试全部通过；生产构建与 diff 格式检查通过。

## 8. 待人工验收

真实双账号环境仍需覆盖：

1. 网易云原曲可播与 QQ 原曲可播。
2. 原平台无 URL、跨平台匹配成功。
3. 首地址媒体失败后同平台第二地址成功。
4. 同平台候选耗尽后跨平台成功。
5. 播放中停用或退出实际平台，剩余平台接管。
6. 手动“本次优先”不改变全局顺序，下一首恢复全局策略。
7. 内容来源、实际来源、歌词来源和听歌记录在双平台场景正确。

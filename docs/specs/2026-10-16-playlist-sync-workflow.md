# 歌单双向同步

> 历史方案：应用歌单双向同步已于 2026-10-18 撤销，当前边界以[歌单职责收敛](2026-10-18-playlist-boundaries.md)为准。原记录保留供追溯。


## 问题与目标

原同步只有整体成功/失败，平台部分写入却无法完整反馈，用户也不能把云端修改同步回来。改为有同步基准的手动检查、拉取、推送，保留平台已经完成的操作。

用户已确认：明确推送时应用歌单为准，移除云端额外歌曲；双方修改中互不冲突的部分自动合并，名称、删除与排序冲突交给用户选择。

## 核心流程

1. 未关联时创建私密云端歌单，保存平台与账号各自的关联。
2. 检查完整云端快照，与上次共同基准和当前应用内容比较，展示双方新增、移除、改名及顺序变化。
3. 云端有变化时先拉取合并。独立修改保留；同时不同改名、删除与移动同一歌曲、不同重排等冲突需要明确选择。
4. 合并只改应用歌单，并把检查的云端版本保存为基准；尚未推送的本地修改继续显示。
5. 推送当前应用更改。检查后云端发生变化时拒绝陈旧推送，先重查合并。名称、加歌、删歌和排序尽力独立执行；某批普通失败不会撤销已完成的操作或阻断其他独立步骤。
6. 显示已加入、已移除、仍未加入及名称/排序未完成的具体结果。重试重新读取并只补当前差异，不盲目重放旧操作。最终无法读回时明确表示尚未确认。

## 基准与冲突

- 记录完整歌曲引用、名称和云端版本，不保存账号凭据。部分推送若可核实最终快照，将实际云端状态作为新基准，本地期望保持不变，差异即待补齐项。
- 旧关联缺少基准时不猜历史，第一次检查后明确选择保留应用内容准备推送，或采用云端内容。
- 歌曲身份按来源与ID识别，双方新增去重合并；一边删除未被另一边移动的旧歌曲可自动合并。仅插入新歌曲不视为移动旧歌。
- QQ不能推送歌曲顺序：本地重排不产生推送任务，拉取可采用云端顺序。网易云按实际存在歌曲的本地相对顺序排序，不能让缺少一首歌曲阻断其他歌曲。
- 拉取过程中本地修改、账号变化、歌单删除会作废旧结果；检查后云端变更也需重新确认冲突。

## 边界

保留本人普通歌单、QQ私密歌单、完整ID和身份、会话、Origin/token及写锁保护。无法取得可信初始快照时不能安全计算差集，停止写入；鉴权失效、换号、取消或归属变化立即停止。已有云端目标删除时不自动重建，也不自动删除本地歌单。

这次不实现自动后台同步、完整提交历史、任意歌单绑定、QQ排序写接口或跨平台混合歌曲同步。删除应用歌单仍保留已关联云端歌单。

## 验收

纯三方合并用例、存档与本地并发保护、平台快照/陈旧版本拒绝、部分成功和重试差集、长歌单批次、实际开发窗口的检查/合并/冲突/推送/部分反馈及深浅主题截图。使用隔离合成账号验收，不改动原有云端歌单。完成类型检查、全量测试和独立复核后本地Squash合入dev/2.4.0，不升级或发布。

# 2.4.0 应用聚合歌单概念记录

日期：2026-10-06。2026-10-12 更新：2.4.0 开发中的首版实现，尚未发布。

## 核心概念

Simple Music 应有自己的聚合歌单。用户可以把不同音乐平台歌单中的歌曲批量加入应用歌单，在应用内统一整理和播放。聚合歌单由应用独立管理，加入和编辑聚合歌单不创建、追加、删除或同步写回来源平台歌单。

播放队列用于当前播放安排，聚合歌单用于长期保存和管理歌曲集合，两者是不同的概念。聚合歌单保存曲目信息与来源，音频下载仍由现有下载功能单独处理。

## 范围约定

- 聚合歌单归属 2.4.0，首版同时支持网易云、QQ、Apple Music 和本地音乐。
- 歌曲、专辑或平台歌单的多选结果，可以批量加入应用自己的聚合歌单；本地音乐支持更多菜单与多选加入。
- 2.3.1 撤掉本轮新增的批量“添加到平台歌单”入口和能力，不提供批量写入网易云、QQ 等第三方平台自建歌单的操作。
- 批量加入播放队列和下载继续保留。
- 用户确认仅调整新增批量写入；原有“漫游保存到平台歌单”等功能不在本次撤销范围。

## 后续实现的验收目标

- 同一应用歌单能够聚合不同来源歌曲，保留来源与原曲目身份，按来源和 ID 去重，并保留加入顺序。
- 聚合歌单持久化，重启后可继续查看和播放。
- 账号退出、平台停用或曲目失效时显示可用状态，不因此删除聚合歌单内容；播放和下载遵守现有来源能力及账号状态。
- 聚合歌单的加入与编辑不向音乐平台发起歌单写入。

## 首版实现边界

- 「我的库 → 应用歌单」提供新建、重命名、删除、逐曲移出及上移/下移排序；批量操作中的「加入应用歌单」可以选择已有歌单或新建并加入。
- 独立实体 `AppPlaylist` 不具有平台 `source`；曲目保留来源、ID 和平台播放所需元数据。`simplemusic-app-playlists` 存储 `{ version: 1, items }`，按来源 + `String(id)` 去重并保留首次加入顺序。
- 保存和编辑先写入存档，再发布新状态；写入失败保留旧内容。损坏或未知版本存档保留原始数据并停止写入，界面提供重试读取。首版无旧存档迁移、云同步或第三方歌单写回。
- 收藏不要求已有曲目的平台当前可用，也不筛掉 `playable=false`。展开在线集合和补齐占位详情仍检查来源参与状态、账号会话及取消信号，旧结果不能落盘。查不到详情的 ID 保留为待加载歌曲。
- 音频 URL 不进入收藏存档；本地封面只保存存在标记，展示/播放时按索引 ID 与当前端口/token 重建资源地址。本地文件可用性经只读接口核实，文件移走后仍保留收藏。
- 歌单详情保存完整的离线状态查询结果，不受全局徽标缓存上限影响。平台停用/退出时保留原收藏并显示状态；网易/QQ 有确认的离线文件时可播放，Apple 仍要求独立官网会话。
- 播放全部或追加队列使用当前可用歌曲的副本，跳过暂不可用歌曲；编辑或删除收藏不改变已安排的播放队列。下载继续使用既有网易/QQ 能力，Apple 和本地文件不进入普通下载。

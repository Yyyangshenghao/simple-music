# 2.4.0 架构梳理与重构范围

日期：2026-10-12。状态：初始梳理已完成；第 1–6 节及初始验证记录保留梳理时的历史事实，当前实施进度以第 7 节为准。

初始梳理时，代码基准为 `origin/master` 的 `2d58888b031c7f348a21d408eda293f8653b38ec`（v2.3.6）。当时本地 `master` 已同步，`dev/2.4.0` 从该提交创建，文档位于 `feature/architecture-scope-2.4.0`，尚未升级版本、提交或推送。

## 1. 结论与目标

建议围绕两条已有的 2.4.0 方向做有限重构：**播放生命周期脱离主界面；应用聚合歌单与播放队列、平台歌单分开管理**。不以文件长度作为重写理由。

现有 Electron、内嵌 HTTP API、Provider 能力接口和页面体系可以继续使用。优先建立清晰的状态所有权与可测试边界，再决定后台宿主和音频后端。只把音频引擎搬走不能解决队列推进、控制入口、存储恢复和特殊播放模式的依赖。

[后台播放与游戏模式草案](2026-10-05-simple-music-2.4-game-mode-architecture.md)保留目标和性能验收要求；[聚合歌单概念](2026-10-06-aggregate-playlists-2.4.0.md)保留应用独立管理、不写回平台的约定。本轮更新代码基准并收敛实施边界，不将草案中的待定事项视为已确认。

| Apple Music | [`apple-music-playback.ts`](../../src/lib/apple-music-playback.ts) 在渲染层串行发送控制并轮询状态；受保护网页会话独立出声；频谱采集属于界面能力 | 保留官网会话不等于控制已独立，后台迁移仍需覆盖命令与状态适配 |
| 刷歌 | [`ShuangePage.tsx`](../../src/pages/ShuangePage.tsx) 卸载时 `leave()`，恢复原队列及播放状态；[`useShuangePlayer.ts`](../../src/hooks/useShuangePlayer.ts) 在页面内绑定片段结束与自动续播 | 当前仅隐藏/卸载界面就会走页面清理路径；销毁 UI 前须区分界面离开与结束刷歌会话 |
| 下载任务 | [`offline-cache.ts`](../../src/stores/offline-cache.ts) 在渲染层持有队列、并发调度与取消状态；[`song-downloads.ts`](../../server/routes/song-downloads.ts) 在响应连接关闭时取消文件导出 | 服务端存在不代表下载任务可脱离 UI；不能销毁窗口后静默丢失任务 |
| 聚合歌单入口 | [`BatchTrackActions.tsx`](../../src/components/Playlist/BatchTrackActions.tsx) 支持加入队列/下载等；[`batch-tracks.ts`](../../src/lib/batch-tracks.ts) 按参与平台展开集合，并过滤 `playable === false` 的曲目 | 聚合歌单还未实现，不能直接把当前“可入队”的筛选当成长期收藏规则 |

现有游戏模式已暂停部分视觉、取色、账户界面轮询和 Apple 频谱捕获，并按用户开关保留轻量桌面歌词；这些已有行为应作为兼容基线。以上为源码结论，不是资源收益或真实设备验收结论。

## 3. 建议的职责边界

| 边界 | 应负责 | 不应负责 |
|---|---|---|
| 播放核心 | 当前曲目、队列/索引/随机顺序、播放意图、解析会话、失败回退、自然结束、睡眠停止、特殊续播 | 页面导航、书架、主题、DOM、Toast 展示 |
| 音频适配器 | 普通音频的加载/控制/事件；独立 Apple 受保护会话的控制/状态 | 决定下一首、修改来源策略或维护第二份队列 |
| 主进程 | 应用生命周期、窗口、托盘、全局快捷键、IPC 权限与后台宿主管理 | 把解码和持续音频处理塞入主进程 JavaScript 事件循环 |
| UI 与 store | 发送命令、订阅播放快照、显示错误/歌词/频谱；管理页面及外观 | 自行推进后台队列、另建出声会话或在重连时恢复旧播放存档 |
| 应用聚合歌单 | 自有歌单身份、曲目来源与身份、顺序、编辑及持久化 | 平台写回、音频文件下载、当前播放走序 |

### 播放核心迁移约束

- 先保持现有渲染后端出声，在原进程内拆职责；跨进程迁移在行为边界稳定后进行。React store 暂时保留兼容接口，逐步成为核心的展示适配层，避免一次改完所有页面。
- `PlaybackResolver` 已提供 Provider、同曲匹配和平台参与判断的依赖入口，应复用。只补齐必要的请求上下文、播放偏好、平台/账号状态、存储和通知接口，不新增通用依赖容器或消息总线。
- 核心生命周期显式启动/释放订阅、定时器和解析请求，避免依赖模块导入时的永久订阅。界面卸载仅解除界面订阅，不等于停止核心。
- 保留播放会话、引擎加载和账号会话三类过期守卫；平台状态变化采用递增版本，旧请求不得污染新账号或新播放意图。后台与 UI 不各自维护互不关联的账号会话序号。
- 命令按受理顺序执行；UI 订阅与初始快照须有一致版本，重连期间不能漏掉暂停/切歌。队列仅在变更时同步，进度和频谱按订阅需求发送；无可视化时停止采集和传输。
- 冷启动仍恢复为暂停；UI 重连使用活跃核心快照。持久化迁移需备份、确认写入成功后才标记完成；失败保留旧数据和原窗口，避免丢队列。
- 最近播放记录与听歌上报由播放事件驱动，保留各自触发规则和来源身份；UI 重连只读取历史，不补记一次播放。托盘状态直接订阅后台，不能等待 React hook 转发。
- Apple 不进入普通直链代理、跨源兜底或离线缓存。普通引擎失败不能静默换成 Apple；UI 频谱采集失败也不能中断 Apple 播放。

### 聚合歌单边界

- 使用独立的应用歌单实体和稳定歌单 ID。容器的归属与曲目的 `source` 分开；不为应用歌单新增在线 Provider，也不将聚合曲目统一改成 `source: 'local'`。
- 曲目按 `source + String(id)` 去重并保留加入顺序与原始身份；长期保存元数据，不保存过期直链，不等同于下载文件。
- 保存内容与当前可播放状态分开。退出账号、停用平台或曲目失效后仍保留内容；播放和下载沿用相应来源能力。集合展开期间仍须取消/账号守卫，不能混入旧账号的迟到结果。
- 复用批量选择与集合展开的必要能力，但拆开“保存曲目信息”和“当前可入队/可下载”的过滤策略。保留现有队列和下载行为，不为聚合歌单改掉它们的限制。
- 第一版建议只覆盖创建/重命名/删除、批量加入、移除/排序、持久化和加入播放队列。不扩展平台双向同步、云同步、智能去重或下载体系；本地文件是否纳入首版另行确定。

## 4. 实施顺序与阶段验收

每项从 `dev/2.4.0` 创建独立 `feature/*`，验收后集成。准备性职责拆分可以先做；后台宿主定型和正式窗口销毁必须等待音频验证原型的证据。

| 阶段 | 最小工作范围 | 通过条件 |
|---|---|---|
| R0：基线与边界 | 记录本轮源码、现有测试与待测项；补充受影响行为的回归目标 | 明确现有游戏模式、刷歌卸载、下载和重启恢复语义；不引用历史测试数量 |
| R1：队列职责拆分 | 从 `playlist` 提取队列走序、随机顺序和编辑规则，平台歌单与书架留在原层；兼容现有调用入口 | 顺序/单曲/随机、批量追加、重排/移除、占位补全和清空行为不变；清空使旧播放任务失效 |
| R2：原进程播放核心 | 将会话编排与引擎/平台状态/通知分开；明确生命周期，统一播放入口；保留当前默认引擎 | 暂停/seek 不被迟到解析覆盖；离线优先、坏缓存回退、设备恢复、Apple 和听歌上报维持原规则；没有新增第二路出声 |
| R3：聚合歌单 | 独立实体与存储，再接入批量选择和我的库；播放只向现有队列发命令 | 重启保留内容/顺序，跨源身份正确；账号不可用不删收藏；无平台写请求；编辑收藏不直接改当前队列 |
| R4：后台宿主与系统入口 | 原型达标后迁移核心、持久化、历史记录与控制；迁移已承诺的刷歌/歌词等必要后台能力；受控验证 UI 销毁/重建 | 无主 UI 可手动/自动切歌、睡眠停止及记录历史；返回不重播/洗牌；托盘状态、快捷键和系统媒体键有效；下载有明确的继续/安全暂停与恢复策略 |
| R5：完整验收 | 双平台功能、存储升级/回退、资源与游戏影响验收 | 保留范围无未说明退化，达到约定预算后才将新的游戏模式作为正式入口 |

音频验证与 R1/R2 的准备性拆分可独立开展：对比现有隐藏模式、轻量音频渲染宿主和原生后端候选，先覆盖本地/离线/真实代理流、格式、seek、倍速保音高、淡入淡出、设备切换、媒体控制和目标平台打包。未测前不指定依赖、语言或宿主，也不将现有 MP3 分析解码依赖视为完整播放后端。

原生候选不达标时保留当前后端；职责拆分仍可独立交付，但不能宣称完成释放主 UI 的低资源目标。R4 未迁移的播放路径或活跃下载任务仍需原窗口时，保留原模式，不静默取消任务或改变当前播放模式。

**建议第一项代码工作只做 R1 队列职责拆分**：保持引擎、IPC、存储格式和页面调用不变，先获得可复用的队列行为边界。聚合歌单作为独立功能推进；后台播放逐阶段替换，不把两条工作线塞入一次大重构。

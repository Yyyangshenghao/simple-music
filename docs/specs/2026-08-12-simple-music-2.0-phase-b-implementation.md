# Simple Music 2.0 阶段 B 实施计划

> 后续决策：本文件保留阶段 B 的实施历史。最终方案不再让我的库聚合或提供“全部/平台”筛选；探索与我的库改为共用全局内容平台和侧边 Dock，详见[多平台融合架构设计](2026-08-12-simple-music-2.0-multi-provider-design.md#82-全局内容平台与探索页信息架构)。

> 对应设计：[Simple Music 2.0 多平台融合架构设计](./2026-08-12-simple-music-2.0-multi-provider-design.md)

## 目标

把阶段 A 的 provider 能力真正接入内容界面：网易云和 QQ 可以同时启用，首页、搜索和我的库保留各平台原生语义并独立失败；跨平台混排内容统一显示可访问的来源标识。漫游允许从全部已启用音源选取候选，混合结果只写本地。

## 产品决策

- 升级时只迁移旧 `activeSource` 对应平台；平台还必须处于已登录状态才参与内容。阶段 B.1 进一步要求新登录的平台由用户明确启用。
- 首页发现歌单按平台分段，不比较不同平台的推荐分数。
- 搜索首版按平台分组，不自动合并同名歌曲或歌手。
- 设置中的“音源切换”改为独立启用开关；未登录时开关不可操作，筛选只控制展示，不改变启用状态。
- 混合漫游只写本地；全部曲目来自同一平台时才允许使用该平台已有保存策略。

## 实施切片

### B1：融合基础

- 新增 `ContentHub` 的部分成功、错误归一、取消和过期结果丢弃能力。
- 新增统一 `SourceBadge`，覆盖歌单卡、曲目行、推荐卡和详情标题。
- 为聚合层和来源标识补自动化测试。

### B2：首页与音源账号

- 首页按已启用 provider 渲染独立推荐分区、hero 栏目和歌单分页。
- 单个栏目失败只显示分区内重试，不清空其他平台内容。
- 设置页与账号菜单改为多音源启用，并展示各平台登录状态。

### B3：搜索与我的库

- 顶栏搜索并发请求全部已启用 provider，按平台分组并保留部分成功。
- 我的库并发加载各平台歌单与收藏，提供“全部/平台”展示筛选。
- 关闭 provider 后，新查询不再包含该平台，迟到响应不得落地。

### B4：漫游与收口

- 漫游候选范围改为全部已启用音源或单个平台。
- 混合曲目只生成本地歌单；单平台继续复用对应保存策略。
- 补来源标识覆盖审计、类型检查、全量测试和独立复审。

## 兼容与回滚

- `useMusicService()`、`settings.activeSource` 和旧 `playlistStore.playlists` 暂时保留，供未迁移页面使用。
- 每个页面独立迁移；回滚时可以恢复该页面的兼容 hook，不需要撤销 provider schema。
- 不改阶段 C 的播放解析、同曲匹配和实际播放来源模型。

## 验证目标

- 聚合层覆盖部分成功、取消、禁用后丢弃、稳定顺序和独立分页。
- 同时启用两平台时，首页、搜索和我的库能显示两边内容。
- 任一平台失败或空数据时，另一个平台结果保持可用。
- 来源徽标具有文字或 `aria-label`，不只依赖品牌色。
- `npm run typecheck` 与 `npm test` 全部通过。

## 实施结果

- `ContentHub` 已接管首页、搜索和我的库的多平台并发、部分成功、取消与迟到响应丢弃。
- 首页按平台保留原生推荐栏目；搜索和我的库按平台分组，所有主要内容实体均展示来源徽标。
- 音源设置与账号菜单已改为独立启用；登录态变化会自动刷新对应推荐、歌单和收藏内容。
- 漫游支持“全部已启用音源”与单平台范围；混合结果仅保存到本地。
- provider 适配边界会补齐 legacy 数据的来源字段；异常数据降级为“来源未知”，不再导致页面崩溃。
- 全部在线平台停用时，旧 `activeSource` 不再驱动刷歌请求，而是提示先启用平台。

## 完成验证

- TypeScript 双工程类型检查通过。
- Vitest 全量测试通过。
- Electron/Vite 生产构建通过。
- 真实窗口巡检通过：首页双平台内容、我的库平台分组、漫游范围、音源设置与跨平台搜索均可正常显示。
- 独立复审发现的登录态刷新和全部停用边界问题已修复并补回归测试。

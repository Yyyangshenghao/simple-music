# Simple Music 2.0 阶段 B.1：首页模式与平台可见性

> 状态：原方案实现完成；探索页混合模式已被 2026-08-13 产品决策取代，待后续实现收敛
>
> 插入位置：阶段 B 完成后、阶段 C 播放解析改造前

> 后续决策：本文件保留阶段 B.1 的实施历史。2.0 最终方案取消探索页和我的库的跨平台混排与“全部平台”，改为共用全局内容平台和侧边半隐藏 Dock；详见[多平台融合架构设计](2026-08-12-simple-music-2.0-multi-provider-design.md#82-全局内容平台与探索页信息架构)。全源搜索、漫游与播放降级的多平台能力不受影响。

## 目标

降低多平台来源标识的视觉密度，同时让首页既能专注浏览单个平台，也能通过真正交错的混合推荐体现 Simple Music 的多平台价值。平台只有在“账号已登录且用户明确启用”时，才允许参与任何内容请求、账号操作或播放降级。

## 产品规则

### 平台参与条件

平台必须同时满足以下条件：

1. 账号状态为已登录。
2. 用户在设置或账号菜单中明确打开“启用”。

未登录、登录失效或未启用的平台：

- 不出现在首页模式、搜索结果、我的库筛选和漫游范围中。
- 不发起推荐、歌单、搜索、收藏、红心、听歌上报等请求。
- 不进入播放优先级和跨平台降级候选。
- 只在“音源与账号”管理界面保留登录入口；未登录时启用开关不可操作。
- 退出登录会自动停用；再次登录后不会自动参与，必须由用户重新启用。

### 来源标识密度

设置新增“来源标识”：

- **常显**：所有内容实体始终展示平台徽标。
- **动态（默认）**：徽标默认收起，在卡片悬停、键盘聚焦或显式来源语境中出现。
- **隐藏**：内容实体不渲染平台徽标；平台筛选、设置等必要控制仍使用文字名称保证可理解性。

### 首页模式

- 只有一个参与平台时，不展示模式切换器，直接进入该平台首页。
- 有两个及以上参与平台时，提供“混合 / 网易云 / QQ音乐”纵向模式牌组。
- 切换时内容沿纵向进入与退出，保持与歌单翻牌相同的空间感。
- 单平台模式保留该平台的原生推荐、账号歌单、最近播放和榜单语义。
- 混合模式把各平台的原生推荐入口、发现歌单和账号歌单按来源交错排列；不比较平台推荐分数，也不伪造功能对齐。

## 实施范围

- provider 偏好：来源标识模式持久化、账号与启用双门槛、退出自动停用。
- 首页：纵向模式切换器、单平台视图、混合推荐视图和单平台退化。
- 内容消费者：搜索、我的库、漫游、刷歌与歌单加载统一过滤未参与平台。
- 播放兼容链：原平台未参与时不解析 URL、不上报听歌；降级只选择参与平台。

## 验证标准

- QQ 未登录时，除账号管理入口外，界面不出现 QQ 内容或来源标识，也不产生 QQ 内容请求。
- 登录 QQ 后仍不参与；打开启用开关后才进入首页模式、搜索、我的库、漫游和播放顺序。
- 两个平台参与时可在混合与单平台首页间上下切换；混合内容按来源交错。
- 来源标识三种模式即时生效并持久化；隐藏模式下控制仍有清晰文字。
- 类型检查、全量测试、生产构建和真实窗口巡检通过。

## 实施结果

- provider 设置升级为 schema 2，加入来源标识模式；平台统一以“已登录且已启用”作为参与条件，退出登录立即停用，启动核实账号前不会误清启用偏好。
- 首页加入“混合 / 网易云 / QQ音乐”纵向模式牌组；单平台自动退化且不显示切换器，混合模式交错平台 hero、发现歌单和账号歌单。
- 来源徽标支持常显、动态和隐藏；动态模式在实体悬停/聚焦时出现，在分区标题等显式语境直接出现，隐藏模式仍保留文字控制。
- 搜索、我的库、漫游、刷歌、歌词、音质探测、队列预取、榜单预取、收藏与播放降级统一过滤未参与平台；原平台未参与时不访问原平台，但仍可在参与平台中尝试降级。
- 漫游范围变化会作废网易云远端水合与旧建议，旧平台结果不得迟到写回。

## 验证结果

- TypeScript 双工程类型检查通过。
- Vitest 全量测试通过。
- Electron/Vite 生产构建通过，`git diff --check` 通过。
- 独立复审发现并修复：启动未知登录态误停用、退出失败状态残留、混合 hero 未交错、显式语境徽标不显示、漫游迟到写回、榜单预取队列继续请求和失效原源无法降级。
- 真实窗口巡检因执行环境处于系统锁屏未能完成；双平台混合模式仍需在两个账号均登录并明确启用的环境补一次人工验收。

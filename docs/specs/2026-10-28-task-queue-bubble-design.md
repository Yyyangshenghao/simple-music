# 任务队列重设计：头像分裂浮现的下载 / 伴奏生成队列

> 状态：设计稿已定稿，未实施（2026-10-28，分支 dev/2.6.0）
> 范围：顶栏队列入口、队列面板、下载队列与伴奏生成队列的界面层；两套任务引擎的调度逻辑原则上不动。

## 1. 现状与问题

| 项 | 下载队列 | 伴奏生成队列 |
|---|---|---|
| 引擎 | `src/stores/offline-cache.ts`（`jobs`/`paused`/`queueOpen`），持久化在 `src/lib/download-queue-runtime.ts`（`simplemusic-download-queue`） | `src/lib/karaoke/queue.ts` + `src/stores/karaoke.ts`（`simplemusic-karaoke-queue-v1`），逐首串行、带内存等待 |
| 界面 | `src/components/Layout/DownloadQueue.tsx`，顶栏搜索框与头像之间**常驻**一个 36px 圆钮 | 没有全局入口，只在「我的库 · 应用歌单 · 伴奏」页（`src/pages/AccompanimentsLibrary.tsx`）里有一段“生成队列” |
| 完成后 | 留在列表成为“下载完成”记录，需手动清除 | 任务直接从 `jobs` 移除并进入伴奏库，没有“刚完成”的反馈 |

具体问题：

1. **常驻入口占位**：绝大多数时间没有任务，下载钮仍占顶栏一格，和头像、搜索框抢视线。
2. **加入即弹面板**：`save()`/`saveMany()` 每次都 `queueOpen: true`，在歌单里连点几首下载会反复盖住内容；批量下载同时还弹 toast，反馈重复。
3. **两条队列互不相见**：伴奏生成只能进库页查看，在播放页点“生成伴奏”后无处跟进进度；两边的暂停、重试、取消文案和行为也不一致。
4. **面板层级平铺**：标题、统计、目录卡、四个操作按钮、提示、四个筛选、列表、错误一次性全部摊开（`DownloadQueue.tsx:82-126`），常用的“看进度 / 取消 / 重试”反而埋在下面；目录设置是低频项却占面板上部最大块。面板用 `--sm-bg-base` 实底，不符合当前以我的库菜单透镜为准的流体玻璃体系。
5. **状态混排**：进行中、等待、失败、完成按加入顺序混在一列，靠筛选按钮切换；失败项不醒目。

## 2. 目标

- 入口**常态隐藏**；有任务时从头像“分裂”出来，任务全部收尾且用户已看过结果后再“融合”回头像。参考 Chrome 下载气泡的出现/驻留节奏，但视觉是本应用自己的。
- 一个入口、一个面板，内部分「下载」与「伴奏生成」两个分区，统一任务行、状态与操作语言。
- 加入任务不再自动打开面板；反馈由入口浮现与计数变化承担。
- 顶栏不得出现瞬时跳动（见“切换不许跳动”约定）；新动效归入独立开关。

非目标：不改下载并发、伴奏推理与内存等待策略；不把两套引擎合并成一个；不做任务拖拽排序（列为后续）。

## 3. 入口：从头像分裂

### 3.1 显隐状态机

入口只有两种存在形态：**融合**（不可见，头像单独存在）与**分裂**（头像左侧多出一个 36px 队列钮）。

| 条件 | 入口 |
|---|---|
| 两条队列都没有任务，且没有未查看的结果 | 融合 |
| 任一队列加入任务 / 启动时恢复了未完成任务 | 分裂（若已分裂则只做计数脉冲） |
| 仍有进行中、等待或失败的任务 | 保持分裂 |
| 全部完成且无失败：用户打开过面板看到结果后关闭，或完成后 **90 秒**无人查看 | 融合（未查看的完成记录在面板里保留到本次会话结束） |
| 有失败任务 | 保持分裂，直到用户重试、移除或清除 |
| 从设置页“管理下载”、库页“查看生成进度”主动打开 | 临时分裂并直接展开面板；关闭面板时若无任务则融合 |

> 全部完成的那一刻，进度环闭合并闪一次表示完成（受「队列分裂」开关控制，关闭时只闭合不闪）。90 秒为初值，验收时按实际手感调整。“未查看的结果”由面板 UI 状态记录，不写盘。

### 3.2 分裂动效

- 形态：头像右侧的渐变描边圆先向左鼓出一个小“芽”，芽与头像之间拉出颈部，颈部变细后断开，芽长成 36px 的队列钮停在头像左侧 8px（与现有 `.right` 的 `gap: 8px` 一致）。融合为逆过程。
- 实现建议：用 SVG `feGaussianBlur + feColorMatrix` 的 goo 滤镜作用于“头像外圈 + 队列钮”所在的一个小容器，**只在动画期间挂滤镜**（约 500–650ms），结束后移除，平时没有任何持续滤镜成本。容器不在嵌套 transform 里，避免我的库透镜那次 SVG 滤镜坐标错位的问题；若实测仍错位，退到纯 CSS：用一个跟随弹簧插值的椭圆“颈部”元素过渡。
- 位置让出：队列钮所在槽位宽度从 0 弹簧插值到 44px（36 + 8），搜索框随之**连续**左移，不出现一帧跳变；分裂动画与槽位展开同一弹簧驱动（`springGentle`）。
- 浮现后的轻反馈：新任务加入时队列钮做一次 `tapScale` 量级的脉冲，计数数字滚动。
- 开关：新增独立动效开关 **「队列分裂」**（归入“控件动效”，与“浮层长出”并列），关闭后入口与槽位直接淡入/淡出，槽位宽度仍平滑过渡（避免跳动）；“减弱动态”下同理。按约定配示意。

### 3.3 队列钮外观

- 36px 圆，玻璃底（`--glass-bg-base` / `--glass-border-base`），与头像同高。
- 中心图标跟随正在运行的任务：下载在跑 → 下载箭头；伴奏在跑 → 麦克风；两边都在跑时以最近开始的那条为准（外圈进度环跟随同一任务）；都只是等待或暂停时，以最近加入任务的那条为准。图标切换用交叉淡化，不改变按钮尺寸。
- 外圈环形进度：显示**正在运行的任务**的总体进度（下载按字节、伴奏按 `model/separating` 阶段的 `progress`）；无可量化进度时环做慢速旋转的短弧，不用持续发光。
- 角标：等待 + 进行中的数量；全部暂停时角标替换为暂停小标；有失败时右上加 `--sm-color-danger` 小点（与现在一致）。
- hover 提示：“2 首下载中 · 1 首伴奏生成中”。

## 4. 面板

### 4.1 结构

从队列钮向下展开（复用 `popoverSproutMotion` 同类的从按钮长出的方式，受“浮层长出”开关控制），宽 `min(440px, 100vw - 32px)`，高度随内容、上限 `100vh - 140px`。表面用流体玻璃（以我的库菜单透镜为准，内部通透，不叠白光/灰光层）。

```
┌───────────────────────────────────────┐
│ [ 下载 3 ] [ 伴奏生成 1 ]        ⏸  ⋯  │  ← 分段 + 本分区暂停/继续 + 更多
├───────────────────────────────────────┤
│ 进行中                                  │
│ ▣ 晴天 · 周杰伦  网易       62% 4.1/6.6MB ✕│
│ 等待 2                                  │
│ ▣ 七里香 · 周杰伦  QQ          等待下载 ✕│
│ ▣ …                                    │
│ 失败 1                       全部重试   │
│ ▣ 稻香 · 周杰伦  无可用音源       重试 ✕│
│ 已完成 4                     清除      │
│ ▣ 夜曲 · 周杰伦            在文件夹中显示│
├───────────────────────────────────────┤
│ 保存到 ~/Music/SimpleMusic   更改目录    │  ← 单行页脚，路径省略 + 完整提示
└───────────────────────────────────────┘
```

- **分段**：「下载」「伴奏生成」两段，带各自未完成数。打开时默认落在“最近有活动”的分区；从伴奏入口打开时直接落在伴奏生成。分段指示条受“标签指示条”开关控制。只有一个分区有任务时另一段仍显示（数字为空），保证切换时高度区稳定。
- **按状态分组**而非筛选按钮：进行中 → 等待 → 失败 → 已完成，空组不显示组头。每组组头右侧只放与该组相关的一个批量操作（失败：全部重试；已完成：清除）。
- **右上动作**：暂停/继续只作用于当前分区；`⋯` 收纳低频项（取消全部等待、打开下载目录）。去掉现在常驻的四按钮条。
- **页脚**：当前分区的保存目录，一行展示，“更改目录”悬停提示“只影响之后加入的任务，已有文件保留”（DESIGN.md 要求保留的边界说明）。目录读取失败时页脚变成错误行 + 重试。
- **暂停提示**：分区暂停时在分段下方显示一行“已暂停，正在进行的任务会完成”；重启恢复的任务同样以暂停态等待，提示“上次未完成的任务，继续后开始”。

### 4.2 统一任务行

| 区域 | 内容 |
|---|---|
| 左 | 40px 封面缩图（走 `api.coverImage()` 缩图，勿原图直出） |
| 中上 | 歌名 · 歌手；`SourceName` 来源；伴奏行另附模型名（如“MDX-Net 标准”） |
| 中下 | 状态文字 / 进度条 + 数值；失败显示原因（红色），完整原因放 title |
| 右 | 单个主操作 + 取消/移除（✕） |

状态映射（文案沿用现有，统一口吻）：

| 统一态 | 下载 `status` | 伴奏 `phase` | 进度显示 | 行操作 |
|---|---|---|---|---|
| 等待 | `queued` | `queued` | “等待下载 / 等待生成”，暂停时“已暂停” | ✕ 取消 |
| 等待资源 | — | `waiting-memory` | “等待内存释放” | ✕ 取消 |
| 进行中 | `resolving`/`saving`/`exporting` | `resolving`/`model`/`preparing`/`decoding`/`separating` | 有数值时进度条 + 百分比；下载另附 MB | ✕ 取消 |
| 收尾中 | — | `saving` | “正在保存”，不可取消（沿用 `cancel` 对 saving 的保护） | 无 |
| 失败 | `failed` | `failed` | 原因 | 重试、✕ 移除 |
| 完成 | `done` | （见 5.2 新增） | 下载：文件名；伴奏：“已加入伴奏库” | 下载：在文件夹中显示；伴奏：播放伴奏 |

进度条高度、颜色统一，数值用 `tabular-nums`，行高固定，进度文字变化不引起行高变化。

### 4.3 空态与错误

- 分区无任务：一行引导，下载“在歌曲、专辑或歌单的更多菜单中选择下载”；伴奏“在播放页的麦克风按钮生成伴奏”。
- 伴奏队列存档不可读（`unreadable`）：分区顶部固定错误条，保留现有文案与“原记录已保留”的说明。
- 下载恢复失败（`recoveryError`）：同上，放在下载分区顶部。

## 5. 数据与状态

### 5.1 新增 UI 状态层（不合并引擎）

新增 `src/stores/task-center.ts`（只放界面状态，不持久化）：

- `open`、`tab: 'download' | 'karaoke'`、`seenAt`（最近一次打开面板的时间）、`lastSettledAt`（两条队列全部收尾的时间）、`forcedOpen`（从设置/库页主动打开）。
- 派生选择器 `useTaskCenterSummary()`：合并两边计数、当前运行任务进度、是否有失败/暂停，供队列钮与显隐状态机使用。
- `offline-cache` 里的 `queueOpen`/`setQueueOpen` 迁到这里；`save()`/`saveMany()` 不再打开面板，改为通知 task-center “有新任务”（触发脉冲）。恢复未完成下载时也只让入口分裂，不自动展开。
- `download-queue-runtime.test.ts` 中关于 `queueOpen: true` 的断言随之调整。

### 5.2 伴奏完成记录

伴奏引擎成功后把 job 从 `jobs` 移除，面板拿不到“刚完成”的项。方案：在 `createKaraokeQueue` 中增加内存态 `recent: { jobId, accompanimentId, track, model, at }[]`（上限 50，不写盘），成功分支写入，供“已完成”组展示和“播放伴奏”。`remove()` 删除伴奏时同步剔除对应 recent。

### 5.3 其它入口调整

| 位置 | 调整 |
|---|---|
| `TopBar.tsx` | `<DownloadQueue />` 替换为与头像同组的 `<TaskBubble />`（头像 + 分裂槽位放在同一容器里，便于 goo 滤镜覆盖） |
| `AccompanimentsLibrary.tsx` | 移除整段“生成队列”，换成一行“N 首正在生成 · 查看进度”（点按打开面板伴奏分区）；伴奏列表本身不变 |
| `SettingsPage.tsx` 的“管理下载” | 改为打开面板下载分区（强制分裂） |
| `MoreMenu.tsx` / `AccompanimentPanel.tsx` | “生成失败，查看队列”等文案点按打开面板伴奏分区；“已加入伴奏生成队列” toast 在入口可见时省略 |
| `BatchTrackActions.tsx` | 批量下载保留一次 toast（含数量），不再打开面板 |
| 设置 · 控件动效 | 新增「队列分裂」开关与示意 |

## 6. 验收

1. 无任务时顶栏只有搜索框与头像；加入下载 / 伴奏任务，入口从头像分裂出现，搜索框平滑左移，录屏逐帧检查无跳变。
2. 连续在歌单里点 5 首下载：面板不弹出，计数逐次脉冲；批量下载只出一次 toast。
3. 两分区同时有任务：队列钮图标与进度环跟随正在运行的任务，计数正确；分段切换高度不跳。
4. 下载全部完成时进度环闭合闪一次；不打开面板，约 90 秒后融合；打开看过后关闭立即融合；有失败时一直保留。
5. 重启恢复未完成下载 / 伴奏任务：入口分裂、两分区均为暂停态，提示正确，不自动展开面板。
6. 关闭「队列分裂」开关、开启减弱动态：入口淡入淡出，槽位仍平滑过渡。
7. 深浅主题、默认与最小窗口（顶栏 < 1100px 断点）截图；长歌名、长路径省略并有完整提示。
8. 性能：入口静止时无滤镜、无持续动画（只有运行中的环形进度在动）；面板关闭时不渲染列表。
9. `npm run typecheck`、`npm test`（含 `download-queue-runtime.test.ts`、`karaoke/queue.test.ts` 的更新）通过。

## 7. 分步实施建议

1. task-center 状态层 + 去掉自动弹面板（行为改动最小，先上）。
2. 新面板（分区、分组、统一任务行、页脚目录），先替换下载，再接伴奏与 `recent`。
3. 队列钮外观与显隐状态机（先用淡入淡出 + 槽位过渡）。
4. 分裂/融合动效与「队列分裂」开关。
5. 库页、设置页、播放页入口改接，截图验收。

## 8. 已定事项（2026-10-28 确认）

1. 队列钮图标跟随正在运行的任务，不用叠层图标（见 3.3）。
2. 全部完成后进度环闭合并闪一次；无人查看时 90 秒后融合，看过后关闭立即融合（见 3.1）。
3. 伴奏“已完成”记录只在本次运行中保留，不跨重启；持久结果以伴奏库为准（见 5.2）。
4. 本版不做等待任务的排序（拖拽、“优先处理”），列入后续。

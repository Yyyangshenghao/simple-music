# 2.4.0 独立音频宿主验证原型

日期：2026-10-12。状态：R4 前置原型已实现，正式后台播放迁移及资源验收尚未完成。

## 目的与边界

验证现有 `AudioEngine` 能否在独立轻量渲染窗口中运行，控制窗口销毁后仍保持播放、顺序推进和定时停止。它是可丢弃的宿主候选验证器，不代表原生后端已选定，也不代表 R2 的正式播放核心已经跨进程迁移。

原型不加载正式 `electron/main.ts`、React 界面或 player/playlist store，不接入正式游戏模式，不迁移用户队列、账号、设置、收藏或下载任务。使用系统临时目录中的 `simplemusic-playback-probe` 作为独立测试资料目录；选择测试文件夹会在该目录建立本地索引。停止原型不会删除原音频文件。

原型不加载 Apple 受保护播放会话，也不实现网易/QQ 曲目解析或失败兜底。公开直链输入只验证既有 `/api/audio` 代理到引擎的路径，不能用公开样本代替真实平台和账号场景验收。

## 启动与操作

在已安装依赖的仓库运行：

```bash
npm run dev:playback-probe
```

该命令使用独立 Vite 配置与 `out-probe/` 输出，不覆盖正式 `out/`，正常安装包的 `out/**/*` 白名单也不包含原型。不要将原型目录手动并入正式安装包。

1. 选择仅含测试音频的文件夹。导入后的队列保持停止，点击播放才起播。顺序播到末尾后暂停；原型不实现正式队列的随机和单曲循环。
2. 用播放、暂停、上下首、定位、音量、倍速检查现有引擎。设备变化只计数，不自动重建输出；音高保持与淡入淡出沿用现有引擎，仍需听感和设备实测。
3. 播放中点击「销毁控制界面并自动返回」。这是 `BrowserWindow.destroy()`，不是隐藏 DOM。实验倒计时内，Dock 激活或第二次启动均不提前恢复窗口；到期只重建控制窗口，查询活跃宿主快照。实验之外的激活只恢复控制窗口。
4. 对比返回前后的会话标识、曲目、进度、加载次数和自然结束次数。单纯返回不得增加加载次数；窗口不存在期间的自然结束可以正常增加加载/结束次数。
5. 设置定时停止后销毁控制窗口，返回应已停止且截止状态清空。暂停期间重建应保持暂停，不能因读取快照而起播。
6. 点击「读取记录」或「导出报告」。报告记录窗口生命周期、播放节点和进程采样，不保存音频直链、API token 或本地文件路径。以 destroyed/created 的时间差、`controlOpen: false` 的样本及区间内播放节点共同确认无控制窗口，不能只凭返回后仍是同一会话判断。

若桌面测试工具无法读取页面无障碍内容，可以仅在功能验收时使用：

```bash
npm run dev:playback-probe -- -- --force-renderer-accessibility
```

该条件必须记入验收记录；不要混用其数据进行默认运行条件的性能对比。输入与快捷键使用标准编辑菜单，数字输入仍由 IPC 验证有限范围。

## 所有权与安全

- 隐藏音频窗口持有一个引擎、当前测试队列和会话；控制窗口只发命令、显示快照。没有第二路正式播放器出声。
- 控制与音频使用不同的临时 session partition，窗口开启沙盒、上下文隔离并关闭 Node 集成。拒绝新窗口、外部导航及非必要权限。
- 主进程按固定窗口、主 frame 和精确入口校验 IPC。控制页不能发送私有队列或任意本地路径；本地音频只能来自用户选定文件夹的索引 ID。
- 公开流仍经过既有 Origin/token/上游地址检查，拒绝内网地址及 URL 中的账号密码，不放宽正式 Server 边界。
- 快照带会话标识与递增版本。订阅先于初始查询，控制页丢弃旧版本，队列内容和 URL 不随进度广播。没有控制窗口时暂停进度广播，语义状态仍供主进程记录。
- 宿主崩溃或主 frame 重载时进入明确错误态并释放旧窗口，不自动启动替代输出。宿主源码修改引起 Vite 完整重载时，需要重启原型。
- 主进程请求有超时和数量上限。关闭控制窗口、启动中退出、迟到文件夹扫描均不得重新创建播放会话或替换新选择。

## 采样口径

主进程每 2 秒调用一次 `app.getAppMetrics()`，首次调用仅预热。CPU 是 Electron 返回的区间百分比；内存字段记录 KiB，工作集相加可能重复计入共享页。只保留最近 900 个样本和 200 条生命周期/播放事件。读取报告不会额外调用指标 API，避免改变 CPU 采样区间。

播放事件只记录状态、曲目、加载/结束次数、错误、设备或定时截止变化，以及成功受理命令时的白名单快照。定位命令因此可保留目标位置，普通每秒进度不记事件。快照查询和订阅切换不额外记播放节点，过期或无效回复先拒绝，再决定是否记录。

报告是开发构建的辅助证据，未记录 GPU 利用率、游戏帧时间或正式安装包成本。可见控制窗口也不是完整正式 UI，不能将它的释放差值当成正式游戏模式收益。正式预算、同源码对照基线、预热与多轮稳态测量仍按[后台播放方案](2026-10-05-simple-music-2.4-game-mode-architecture.md)执行。

## 本轮验证记录

- 环境：macOS 27.0.1、arm64、Electron 42.11.0，开发构建；功能补测使用 `--force-renderer-accessibility`。使用自行生成的 WAV 和多格式短音频，不使用用户收藏或账号。
- 早期检查确认了销毁/重建和同一会话恢复，但补测报告发现系统激活可使控制窗口提前重建，因此不能用早期记录证明持续无界面。已修复实验倒计时内的激活/第二实例恢复，回归在修复前失败、修复后通过。
- 修复后的会话 `b00af469` 导出记录显示：第一次控制窗口不存在 45053 ms，其间有 23 条 `controlOpen: false` 样本，MP3 到 Opus 六首均自然结束并推进，WMA 明确进入 `MEDIA_ERR_4`；同一音频宿主保持存活。
- 同一会话将 WAV 暂停并定位到 2 秒，销毁控制窗口 10049 ms 后仍保持暂停，位置约 2 秒（后续恢复命令快照为 2.248 秒），加载次数保持 8。随后恢复并设 3 秒停止，窗口不存在的 10041 ms 区间内记录到停止和截止清空；返回为停止，加载次数仍为 8、自然结束次数仍为 6，未因重建起播。
- 公开 MDN CC0 MP3 样本经现有 `/api/audio` 代理起播并自然结束。仅验证公开代理路径，不代表网易/QQ 解析、登录、地址过期或长流验收。
- 已读取生命周期及资源记录，观察到控制窗口 destroyed/created 事件与音频宿主存活。实机报告曾显示 900 条样本，但运行含中断和长空闲，不是连续稳态对照，本轮不形成 CPU/内存收益结论。
- 自动回归覆盖暂停/定位与迟到播放结果、自然结束、定时停止/取消、释放、IPC 发送者和参数、旧会话/敏感字段过滤、限时窗口重建及激活干扰、启动中退出、迟到扫描、宿主崩溃/重载、900 条采样/200 条事件上限和导出失败。全量 237 个文件、2036 项测试及类型检查通过，独立复核通过；未运行正式构建。

| 自生成样本 | 编码与采样条件 | 实测结果 |
|---|---|---|
| MP3 / FLAC | 各 44.1 kHz、单声道、约 6 秒 | 起播、自然结束与推进通过 |
| M4A / AAC | AAC，44.1 kHz、单声道、约 6 秒 | 起播、自然结束与推进通过 |
| OGG | Vorbis，44.1 kHz、双声道、约 6 秒 | 起播、自然结束与推进通过 |
| Opus | Opus，48 kHz、单声道、约 6 秒 | 起播、自然结束与推进通过 |
| WAV | PCM s16le，16 kHz、单声道、6 秒 | 起播、自然结束通过；错误后可手动切到该曲继续播放 |
| WMA | WMAv2，44.1 kHz、单声道、约 6 秒 | `MEDIA_ERR_4`，未通过；索引接受不等于引擎可解码 |

以上是所列样本的功能结果，不覆盖同一容器的全部编码变体或音质听感。WMA 兼容性、真实网易/QQ/离线流、长流、断流与地址过期、实际设备切换、系统媒体键、Apple、Windows、目标架构打包、原生后端候选及资源/游戏预算仍待验收。

只有上述门槛补齐后才能决定后台宿主并迁移正式核心、历史、持久化、托盘、全局快捷键、刷歌和下载策略。现有游戏模式保持原路径。

# 2.4.0 歌单职责收敛

## 问题与决定

应用歌单负责聚合网易、QQ、Apple 和本地歌曲；平台歌单负责直接管理对应账号的歌单。取消应用歌单与平台歌单之间的检查、拉取、推送和冲突合并，用户不再维护两份内容的一致性。

## 本轮范围

- 应用歌单保留新建、改名、删除、排序、移除和播放；保留“加入应用歌单”，跨来源混合收藏无同步限制。
- 我的库“歌单”页提供对应平台的新建入口；详情页提供本人普通歌单改名，以及通过歌曲多选加入/移出平台歌单。创建后的歌单允许为空，默认私密。
- 网易与 QQ 通过独立直接管理接口执行增量操作；QQ 首轮仅开放已验证的私密普通歌单。Apple 保持只读，不猜测写入能力，不匹配其他平台歌曲。
- 批量加入平台歌单只接受同一支持来源，保留来源身份；添加不覆盖原曲目，移除仅作用于明确选中的曲目。不提供整体替换、自动同步或歌曲顺序推送。
- 旧本地收藏、漫游歌单和已创建的云端歌单不迁移、不删除；旧同步元数据仅兼容读取，不再发起网络操作。QQ 红心收藏迁移到通用账号会话接口。

## 交互与边界

新建入口位于平台歌单列表，明确平台与私密属性；改名和移除需服务端回查本人普通歌单归属。平台删除整个歌单、一次性跨平台复制、后台同步不在本轮范围。

写入绑定当前账号与会话，服务器检查真实归属、上游响应、取消与登录变化。已发出的写入无法由取消撤销，失败/部分完成/结果未确认分别反馈，提供刷新而不盲目重放。创建用有限检查点防止重复请求创建多份。

## 验收与实施

1. 新建平台管理契约和两个平台的服务端增量写入路径，复用既有身份及安全检查；撤销旧同步路由注册。
2. 平台能力接入，列表新建、详情管理与歌曲多选加入；移除应用歌单同步 UI 和运行时，保持旧档兼容。
3. 验证归属拒绝、跨来源拒绝、会话变化、部分失败与缓存失效，以及原有 QQ 收藏和漫游路径。
4. 类型检查、全量测试、独立复核；隔离测试配置检查真实 Electron 的深浅主题、最小窗口、空歌单和表单反馈。只用模拟上游，不修改真实账号歌单。
5. 完成后本地 Squash 合入 dev/2.4.0，不更新版本、不发布。

回退以独立功能提交为单位。本轮不删除云端歌单；已正常编辑保存的本地存档不再保留旧同步关联，回退不会恢复这些关联。
